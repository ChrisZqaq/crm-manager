# 销售订单、收款核对与履约共识

## 下单与占货

- 一单支持多个 SKU，销售手动选择各供货仓库、数量、成交单价、客户或散客及销售渠道。
- 正式提交时检查可售数量并原子占货，库存不足明确提示，重复提交不得重复占货。
- 下单占货时固定各供货仓库的成本快照，并预计算提成；后续普通入库不修改历史成本，明确批准的采购纠错除外。
- 客户预留在线下沟通，由仓管先解锁为公共可售，销售再下单，不做指定订单放行。
- 未发货修改同步处理占货和金额，与已收款金额不符时提醒人工处理。
- 所有未发货订单取消统一释放占货、恢复可售；保留已收款凭证，取消不自动表示退款，需要预留时由仓管人工锁回。
- 已发货不直接修改商品、数量或供货仓库。

## 收款登记与快速发货

- 销售选择具体收款账户（银行、微信、支付宝等），填写销售登记收款金额并上传截图；收款时间选填。
- 截图必填，未提交凭证不能进入待出库。
- 系统直接比较手填收款金额与订单金额，无需 OCR；金额不一致时提醒并要求填写原因，确认后允许继续发货。
- 上传截图及金额一致均不等于核实实际到账，第一版不做 OCR、截图自动审核或支付渠道接入。
- 尚未核对时允许发货，到账后置核对；但核对人员已发现问题且尚未发货时，暂停出库。
- 待处理问题由销售补充凭证或处理差额，再由对应核对人员核实；暂停不能仅凭销售改信息自动解除，实际恢复条件需核对通过。
- 履约状态与收款核对状态分别记录，核对问题不改变已发货或已完成的履约事实。

## 到账核对与提成

- 对公银行转账由财务核对。
- 老板私人微信、支付宝账户由老板直接完成到账核对，不再要求财务重复确认该账户到账。
- 发现凭证或金额问题时，标记待处理并填写原因；未发货暂停出库，已发货保持发货状态。
- 对应账户核对人员确认通过，作为提成所需的收款核对通过条件；不因使用私账取消老板的提成复核。
- 正式计入提成必须同时满足：订单完成、收款核对通过、老板提成复核通过。
- 提成按订单毛利的 10% 计算，销售出库运费扣毛利，亏本提成为负，退货不扣提成。补扣资金在线下处理。

## 发货与现场交付

- 快递流程：待确认（已占货）→ 提交收款凭证并确认 → 待出库 → 确认发货 → 待收货 → 销售确认收货 → 已完成。
- 仓管或有出货权限的销售操作发货；选择承运方，提供运输编号，关联订单已选定的出货仓库。
- 承运方先支持跨越、顺丰、货拉拉；跨越和顺丰填写运单号，货拉拉填写平台订单号。
- 一单可有多个运输编号、对应多个出货仓库，不重新选择或擅自改变订单供货仓库。
- 暂不支持分批发货，一次确认整单发货；确认时扣在库数量、解除对应订单占用，不能重复扣减。
- 出库运费默认 0，人工分摊，不改变剩余库存成本。
- 门店现场交付无需承运方或运输编号；满足收款凭证及无暂停出库问题的要求，实际交付后确认完成，同时扣库存。
- 快递订单由销售确认收货后完成，不做物流自动查询或自动确认收货。

## 金额精度

- 数据库金额保存到小数点后 3 位，包括实际业务金额及保存的单位成本、提成金额等；使用精确十进制，不使用二进制浮点保存金额。
- 计算中间精度、舍入方式、单价乘数量及多明细汇总的舍入时点尚未确定，不能自行选择导致账目不一致的算法。
- 对外实际支付、退款或补扣在线下执行，不因数据库精度扩展支付功能。

## 最小验收场景

1. 正式提交并发占货不超卖，重复提交不重复占货。
2. 缺收款截图不能进入待出库；收款时间未填不阻塞。
3. 金额不一致必须提示并填写原因，确认后可发货，但不自动通过收款核对。
4. 未核对可发货；已发现收款问题且未发货时，快递和现场交付均暂停。
5. 发现收款问题时已发货，保留发货状态并阻止正式计入提成。
6. 老板直接核对私账到账，对公由财务核对；提成仍需订单完成及老板复核。
7. 多仓物流编号正确关联；货拉拉平台订单号可用，现场交付不要求物流信息。
8. 数据库金额可精确保存 3 位小数；最终计算验收样例在舍入规则确认后补齐。

## 后续设计边界

- 修改已核对订单金额或收款凭证后，哪些核对与提成复核结果需要重新确认。
- 多个物流编号和仓库的具体关联结构、出库运费录入后的预估提成更新。
- 金额中间计算精度与舍入规则。

上述细节在相应设计时明确，不额外加入 OCR、支付网关、分批发货或复杂审批。
