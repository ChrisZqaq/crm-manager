## 确认顺序

1. [PRD](PRD.md)：确认范围、每个人的操作和进入下一步条件、验收场景，检查有无遗漏。
2. [SPEC](SPEC.md)成本章节：用数字例子确认库存扣减与订单成本、尾差、破损退款、采购纠错和提成复核规则。
3. [数据库设计](DATABASE_DESIGN.md)：确认数据身份、字段关系、唯一性及必要历史记录，再确定模型和数据库约束。
4. 完成SPEC中状态、接口、导入与部署等剩余细节；角色默认值、日期及最小日志方案已确认，实施须遵守SPEC。超出已批准方案的新日志点按AGENTS先确认。
5. 更新所有关联文档，由用户明确确认开发基线后再编码。

草案与共识分别标注。不依赖用户填写完真实库存才能讨论设计，也不以模板已填好代替文档确认。开发测试使用合成数据，用户可提供少量模板样例辅助核对字段及导入；正式库存以已确认的上线暂停出入库窗口中核准的数据为准。

```sh
uv sync --locked

scripts/dev-db.sh start
uv run python manage.py migrate
uv run python manage.py createsuperuser
uv run python manage.py runserver 127.0.0.1:8000
```
