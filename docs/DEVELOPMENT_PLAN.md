## 确认顺序

1. [PRD](PRD.md)：确认范围、每个人的操作和进入下一步条件、验收场景，检查有无遗漏。
2. [SPEC](SPEC.md)成本章节：用数字例子确认库存扣减与订单成本、尾差、破损退款、采购纠错和提成复核规则。
3. [数据库设计](DATABASE_DESIGN.md)：确认数据身份、字段关系、唯一性及必要历史记录，再确定模型和数据库约束。
4. 完成SPEC中状态、接口、导入与部署等剩余细节；角色默认值、日期及最小日志方案已确认，实施须遵守SPEC。超出已批准方案的新日志点按AGENTS先确认。
5. 更新所有关联文档，由用户明确确认开发基线后再编码。

草案与共识分别标注。不依赖用户填写完真实库存才能讨论设计，也不以模板已填好代替文档确认。开发测试使用合成数据，用户可提供少量模板样例辅助核对字段及导入；正式库存以已确认的上线暂停出入库窗口中核准的数据为准。

## 阶段1本地运行

开发环境版本固定为 Python 3.12.13、Django 5.2.17、PostgreSQL 17.11、Psycopg 3.3.6；锁文件固定 Python 依赖。Python与Django版本来自受支持的Django 5.2 LTS系列，PostgreSQL使用受支持的17主版本。上线前仍需按当时受支持的安全维护版本复核并更新锁定版本。

- [Django下载与支持版本](https://www.djangoproject.com/download/)、[Django 5.2数据库支持](https://docs.djangoproject.com/en/5.2/ref/databases/)
- [Python 3.12文档](https://docs.python.org/3.12/)、[PostgreSQL版本支持周期](https://www.postgresql.org/support/versioning/)、[Psycopg 3安装与平台支持](https://www.psycopg.org/psycopg3/docs/basic/install.html)

本机从PostgreSQL官方17.11源码编译到仓库忽略目录`.local/`；构建不需要readline、zlib或ICU。ICU未启用，阶段1查询依赖Python文本归一化，不依赖ICU排序规则。数据库仅监听仓库内Unix socket，不开TCP端口；集群目录、套接字和日志均留在`.local/`，本地开发账号使用socket认证，不适用于生产。

首次准备及日常启动：

```sh
uv sync --locked
scripts/install-dev-postgres.sh
scripts/dev-db.sh start
uv run python manage.py migrate
uv run python manage.py createsuperuser
uv run python manage.py runserver 127.0.0.1:8000
```
