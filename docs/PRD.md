# 第一版产品需求文档（PRD）

状态：**待用户确认的整合草案**。整理日期：2026-10-03。

业务依据是各模块共识文档。本文整合产品范围、操作条件及验收标准；“已确认”指此前讨论已确认的业务，“建议／待确认”不代表已获批准。本文与 [数据库设计](DATABASE_DESIGN.md)、[SPEC](SPEC.md) 一起确认后才进入开发。

## 1. 目标与范围

销售登记一笔订单后，库存占用、出库、客户购买记录、收款核对和提成使用同一份数据，减少重复登记与月底对账。

第一版包含：账号与角色权限、商品及仓库档案、期初导入、采购入库、库存锁定及解锁、客户、销售履约、收款核对、提成、拆箱、赠送、破损处理、盘点、采购纠错、四张报表及 Excel 导出、结构化查询 API。

不包含：未到货需求及订货管理、指定销售配额、保持SKU不变的独立仓库调拨、分批发货、OCR、支付或物流自动对接、散卡／评级卡／回收／寄售、完整售后、银豹同步、营销自动化、完整操作审计、Bot／MCP 服务。

使用者为销售、仓管兼财务、老板、管理员。人员可以兼任；业务权限按固定角色的开关配置，兼任取并集。超级管理员不能绕过业务校验。

## 2. 完整操作流程及下一步条件

| 环节 | 操作人及操作 | 生效／进入下一步条件 |
| --- | --- | --- |
| 上线准备 | 管理人员维护商品、仓库、账户和角色；仓管提交期初表 | 模板关联、数量、成本校验全部通过；切换库存已核对 |
| 到货入库 | 仓管填写一个供应商、一个仓库及明细 | 实收数量、进价、运费分摊、预留及破损合法；凭证选填 |
| 预留解锁 | 仓管按线下分配解锁客户预留 | 解锁不超过已有预留；解锁后成为公共可售，不保护指定销售 |
| 销售下单 | 销售选客户或散客、渠道、SKU、仓库、数量和成交价 | 正式提交整单检查可售并占货；不足则整单失败；固定成本、显示预估提成 |
| 收款登记 | 销售选账户、填实收金额、上传截图 | 截图必填；金额不同需填写原因并确认；收款时间选填，进入待出库 |
| 快递发货 | 仓管或兼任仓管的销售填写承运方和物流编号 | 无收款问题暂停；整单一次发货，所有供货仓库有对应物流信息；扣在库并释放占货 |
| 现场交付 | 有权限人员确认实际交付 | 同样满足凭证及未暂停条件；不需物流编号，扣库存并完成订单 |
| 确认收货 | 销售跟踪客户收货并确认 | 快递订单已发货，销售确认后完成；不自动确认 |
| 到账核对 | 对公由财务、私账由老板核对 | 可在发货后核对；问题必须填写原因；未发货发现问题则暂停，已发货保留履约事实 |
| 问题处理 | 销售补充凭证或处理差额 | 对应核对人员重新核对通过才能解除问题暂停，销售修改不能自行解除 |
| 提成计入 | 老板复核 | 订单完成＋对应账户到账核对通过＋老板提成复核通过，三者缺一不可 |

截图上传不等于到账核对。订单完成也不等于正式计入提成。未核对可发货的时效规则已经确认，界面应明确区分这些状态。

| F10 | 付款与核对 | 一单一笔收款；截图必填、时间选填；差额说明后可发货；已发现问题未发货暂停；变更金额账户截图使核对失效 | [销售](SALES_FULFILLMENT.md) |
| F11 | 交付 | 一次整单发货，多物流号关联供货仓库；跨越／顺丰运单号、货拉拉平台订单号；现场交付不填物流 | [销售](SALES_FULFILLMENT.md) |
| F12 | 提成 | 整单毛利10%，允许负提成；完成＋到账核对＋老板复核才计入；退货不扣提成，售后模块暂缓 | [销售](SALES_FULFILLMENT.md) |

| F15 | 盘点 | 每月仓管盘点、老板确认差异；先查错单，无法追溯差异用盘点调整；不覆盖余额或绕过非负校验 | [共识](PROJECT_CONSENSUS.md) |
| F16 | 采购纠错 | 无后续影响可改；有影响仓管提交老板确认；预览库存成本、订单及已审核提成变化；失败整体回滚 | [采购](PURCHASE_RECEIVING.md) |
| F17 | 四张报表／导出 | 库存、销售、收款核对、提成；导出当前筛选及授权范围；销售默认发货口径，现场交付按交付时间；销售省市筛选分组按订单地址快照 | [报表](CUSTOMERS_REPORTS.md) |
| F18 | 查询API | 网页与API共用业务规则；Agent实时读结构化数据，附字段、筛选和口径说明；无自然语言写操作 | [共识](PROJECT_CONSENSUS.md) |

已收款未发货取消释放占货并保留凭证，退款线下处理。地址与备注变化不触发成本或收款重审；实际已发生的交付事实不能因重审倒退。影响提成的普通修改需要重新复核，采购纠错按专门流程处理。

已确认采购纠错审批同时确认影响清单中原已审核提成的新金额，不逐单重复审核；原未审核订单仍走正常提成流程，不自动计入。已发放部分保留差额，线下补扣后销售标记完成。

出库运费下单默认0，发货／现场交付时填已知运费并更新毛利提成；未知仍可出货并后补。后补或修改不改变商品及剩余库存成本，原提成复核失效、需老板重新复核；线下补扣人工处理，不增加运费支付管理。

凭证仅支持JPEG、PNG、WebP图片，单张最多10MB、一单可多张；收款至少一张，入库选填，访问沿用单据权限。无PDF、OCR、自动压缩或独立文件管理模块。

期初录错复用采购纠错规则：无后续影响由仓管修正；有影响提交库存、订单成本和提成变化预览，老板确认后整体重算，保留原因前后值、非负校验，不重导、不另增审批、不把期初改为采购单。

低库存提醒已确认：后台维护一个全局默认阈值，不区分单位或仓库；入库明细提供可选SKU专用阈值输入框，留空使用全局默认值，另提供关闭该SKU提醒按钮。SKU设置各仓共用，各仓按可售数量小于或等于有效阈值判断；库存表标记并可筛选，只做页面提醒，不增加IM、短信、邮件或定时任务。阈值非负整数，0表示可售为0时提醒；全局初始值为5；后台提供全局开关，关闭后所有SKU不提醒，保留各项设置，重新开启后按原配置判断。

生日提醒已确认：选填公历生日，客户列表提供“今天生日”筛选及标记，按北京时间月日匹配；每个账号的个人页面开关默认开启，本人可关闭或恢复，仅影响本人页面、不影响其他人员、不删除生日资料，不增加逐客户开关。2月29日仅当天匹配，非闰年不另日提醒；客户查看权限不变。无主动消息、定时任务、提前多天提醒或营销自动化。

低库存全局及SKU提醒默认开启；老板／管理员管理全局开关及默认阈值，仓管、老板／管理员管理SKU阈值与关闭／恢复，普通销售只查看，兼任仓管获得SKU设置权限。

## 4. 数量与金额规则

- 可售＝在库－订单占用－客户预留－囤货－破损；数量为整数，受限合计不得超过在库。
- 卡牌产品语言版本必填、不默认简中；周边可空；同产品各SKU共用语言。导入缺卡牌语言时提示具体行，补齐后才能入账。
- 仓库＋SKU移动平均；入库成本＝数量×采购价＋明细分摊采购运费；平均成本＝剩余成本金额与本次成本金额之和／入库后数量。
- 锁定、占货、破损均仍在库并保留成本。占货不减少实物，发货才减少实物。
- 正式下单固定订单成本；普通后续入库不改历史订单。明确批准的采购纠错可重算历史订单和已审核提成。
- 已确认分别记录两种成本：订单毛利及提成使用下单成本快照；库存金额按实际发货或现场交付时的移动平均成本扣减。
- 订单单位成本先四舍五入固定3位，订单行成本＝固定单价×数量，减量沿用该单价；与高精度库存扣减的微小差额不混入订单成本或提成。
- 金额保存3位十进制，半值远离零；高精度计算、保存时舍入；明细金额先保存再汇总。
- 整单毛利＝明细成交金额合计－明细成本金额合计－销售出库运费；整单提成＝毛利×10%，最后舍入，不能逐行舍入提成再相加。
- 已确认库存尾差处理：按当前剩余成本金额÷剩余数量×出库数量计算并保存3位；清空该仓库SKU时扣完剩余成本，数量与成本一同归零，不更改已固定的订单成本和提成。
- 已确认破损退款按处理时移动平均成本扣库存及破损数量，实际退款与扣减差额另行记录，不修改原入库，不摊其他商品，不重算历史订单或提成；原单录错才走采购纠错。
- 数量统计携带单位，不能把箱、盒、包混加。纠错回放细节见 SPEC 待确认设计。

## 5. 最小页面范围（建议）

复用框架管理后台维护基础资料、员工和角色；业务网页包括库存查询／入库、锁定解锁、客户、订单及收款发货、待核对与待复核、库存其他操作、四张报表。动作可以在同一页面完成，不要求每个实体单独页面。

不先做独立商城、购物车、实时大屏或复杂装修。销售“选商品下单”的使用方式已满足当前需求，现有需求不要求购物车或保存草稿。

## 6. 核心验收场景

| 编号 | 验收结果 |
| --- | --- |
| A01 | 入库60预留50，可售10；解锁20后可售30；下单20后占用20、可售10；取消后可售30，不自动锁回 |
| A02 | 可售10，两销售各下单8，最多一单成功；失败单无残留占货；重复提交／入库／发货不重复执行 |
| A03 | 多仓订单任何一条库存不足，整单无变化；改订单失败保留原单、原占货、原核对结果 |
| A04 | 采购价为空、数量负数、受限超量不能入库；采购运费只计入一次；普通新采购不改历史订单成本 |
| A05 | 无截图不能出库；有差额无原因不能继续；有原因可继续但未自动核对通过；已发现问题未发货暂停 |
| A06 | 已发货发生收款问题保持发货事实，不能计入提成；私账由老板核对；三个提成条件齐备才计入 |
| A07 | 多仓物流关联正确；货拉拉订单号可填；现场交付无需物流，重复交付不再扣库存 |
| A08 | 1.2345保存1.235、-1.2345保存-1.235；两条毛利各0.005的订单提成为0.001 |
| A09 | 同仓或跨仓拆箱不凭空增加成本，失败无单边库存变化；换货不增库存成本；赠送不计销售；破损退款运费损失不摊其他订单 |
| A10 | 纠错须有影响预览；历史负库存拒绝；审批时数据变化需重新确认；库存及提成重算整体成功或失败 |
| A11 | 本人范围不能越权查询／导出；管理员也不能绕过截图、库存校验；权限更改和必要审批有记录 |
| A12 | 期初导入错误定位到表行字段，失败无部分库存；四报表导出与同一筛选查询数值一致 |

A04、A09、A10的具体成本数字用例须在成本算法确认后补全，不能仅凭页面可用宣布验收通过。

## 7. 确认清单

以下不属于新增模块，而是实现现有功能需要明确的边界；建议逐组确认。

1. **成本与纠错**：订单成本与库存扣减分别计算、零库存尾差、破损退款成本扣减、纠错审批同时确认原已审核提成、按系统实际生效顺序重算已于2026-10-03确认；不按人工填写的单据日期重排。具体计算样例及实现算法仍需补全和验证，详见 SPEC 第4节。
2. **占货与盘点**：已确认库存不足覆盖占用／锁定时，先用现有操作人工处理再审批，无自动联动；盘点至审批期间在库数量变化，重新核对受影响商品后提交，无自动追差；仅占货／解锁不重盘，仍校验受限数量；成本变化刷新金额影响供老板确认。
3. **商品与导入**：卡牌语言必填、不默认简中、周边可空；条码可空、重复提醒并确认；IP前缀＋至少4位流水号、各IP独立人工编号、全局唯一、不改号不复用均已确认。产品按IP、类型、系列、名称、语言、官方编号一致识别候选，人工确认预览；冲突核对，不模糊归并或静默覆盖。其他IP前缀仍由用户指定。
4. **客户与权限**：客户归属、大陆省市地址及快照、联系方式及收件字段必填、现场交付散客例外、角色默认权限及账户核对边界均已确认；初始配置见 [登录与权限](ACCESS_CONTROL.md)。
5. **日期及提醒**：滚动日期及提成日期已确认；低库存单一全局默认5、SKU可设专用值或关闭、各仓分别判断及全局关闭已确认；公历生日仅今天筛选标记、可关闭无主动消息已确认；入库统一核对摘要替代自动异常大值提醒、不增加阈值配置，保留硬校验已确认。
