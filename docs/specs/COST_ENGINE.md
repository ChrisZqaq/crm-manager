## 1. 金额与数量

数量用整数，金额用Decimal及NUMERIC(20,3)，中间精度50，保存时ROUND_HALF_UP；超出数据库容量明确拒绝，不截断或转浮点。字段容量是技术上限，不增加异常大值审批。平均成本由剩余成本金额／在库计算；库存0时成本0、平均成本显示空值，真实零成本商品仍合法。

入库成本=数量×采购单价＋本行采购运费；明细保存3位再汇总。订单单位成本先固定3位，订单行成本=固定单价×当前行数量；仅减量沿用该单价，增量／换SKU／换仓整单重新固定。

库存出库函数只接受0<出库数≤当前在库：清空扣全部剩余成本，否则扣round3(剩余成本／数量×出库数)。销售实际出库、赠送、拆箱来源、破损退款和盘亏共用这个函数。库存出库成本与订单成本分别保存。

毛利=成交行金额之和－订单成本之和－销售运费之和；提成=round3(整单毛利×0.10)。负毛利、负提成合法。销售运费仍按行人工分摊，汇总一次，不另保存可独立编辑的第二个运费总额。

## 2. 同一事务及实际生效顺序

用一条固定的业务控制记录作为PostgreSQL行锁。所有库存、订单金额／收款核对／提成及纠错写操作，事务开始先锁该行，再锁订单及按仓库ID、SKU ID排序的余额，检查权限、状态及输入，然后写入业务记录和流水。基础资料普通查询不获取该锁。上传、图片校验、Excel解析及预览计算放在锁外；关联确认在锁内。

该控制记录保存最后业务序号，成功操作在锁内递增并分配序号；锁持有到事务提交，后一事务才能取得锁并分配下一个序号，因此序号与已提交业务生效顺序一致。失败事务不留下序号、流水或余额变化。业务时间以服务端时区时间记录，人工单据日期不参与排序。

首次余额创建也在锁内，通过仓库SKU唯一约束兜底。一个操作可含多条行流水，同次拆箱的来源与目标不可拆成两个可分别审批的事件。通过框架事务实现，不增加Redis、队列或分布式锁。

预览使用同一个只读REPEATABLE READ事务，在首个数据查询前设置隔离级别和只读属性，然后读取控制序号和相关记录；多条查询共享该快照，不能使用普通READ COMMITTED多次读取冒充一致性快照。不长期持业务锁。批准时取得业务锁，检查预览时的最后业务序号与相关版本；不一致返回重新预览，不自动批准改变后的金额。初版保守地让任何新的受协调业务操作都使旧纠错预览过期，避免漏掉新跨仓链；不提前实现精细依赖追踪。

## 3. 业务输入与有效结果

`business_operation`记录一次有效动作：序号、唯一操作标识、动作类型、操作人、时间、具体业务外键、最小输入JSON及成本版本。输入只包含重建库存和订单计算所需事实，如采购数量价格、当时订单行身份仓库数量成交价、固定成本方式、锁定解锁量、拆箱两端、实盘数量及计价依据，不记录普通浏览和全部字段审计。

`inventory_movement`记录该动作各余额的数量、四类受限数量及成本增减，关联操作和实际单据来源。已生效输入无普通编辑／删除入口；原采购或期初录错由批准的纠错替代其有效输入，不把纠错当成今天额外采购。

当前业务行、流水有效成本及余额只保留一份有效计算结果。纠错记录保存原有效输入、修正输入、修改前后影响及批准人时间；批准后更新相应计算字段和版本，不再追加一份同样的有效出入库供报表重复累加。业务输入顺序不改，人工输入事实不因重算被覆盖。

旧流水金额可因明确纠错更新，但必须有纠错前后对比可解释，普通用户不能随意编辑。无需保存每次全库历史快照；重复纠错以最新有效来源数据重建，差额相对于上次批准金额，旧纠错及补扣记录不删除。

## 4. 顺序回放

先完整校验纠错目标和允许修改字段，在只读快照内按业务序号扫描已生效操作，从期初开始重建与修改有关的仓库SKU、订单成本。初始关联键取原输入与拟议输入的仓库SKU并集，沿实际拆箱关系扩展到完整关联集合，不能只处理改前或改后一侧。采购仓库属于单头，只允许整张采购单改仓，涉及全部明细，不接受单行换仓；期初行的仓库按行更正。输入量可逐批读取，不把全部图片或全库数据塞入内存；第一版先保证结果正确，不做检查点调度器。

1. 期初、采购：使用最新批准来源输入；本次预览只在临时状态中覆盖申请修改的数据。
2. 下单：按当时平均成本固定订单成本快照，保存各行稳定ID；仅减量沿用对应快照；整单重新固定则用修改时点的临时平均成本。成交价变化只影响该订单金额，不改变库存。
3. 解锁、取消：更新受限数量；取消订单不能在报表继续计有效销量或可结算提成。
4. 销售交付：已发生交付的SKU、仓库和数量保持原事实，按重建的当时移动平均扣库存金额。取消重审不倒退交付状态。
5. 拆箱：来源扣减与目标增加同时处理，来源扣减成本全部转目标，随后扫描目标SKU的后续事件；即使来源后来清空，也不能漏掉已转移成本的目标链。
6. 换货：减少破损、数量及成本总额不增；退款：原退款数量及实际到账金额不变，按重建当时平均成本重新计算库存扣减及差额，不执行第二次真实退款。普通新退款本身不触发历史纠错。
7. 盘点：保持实盘观测，差量=实盘数－重建账面数。差量为负时按该时点重建库存的移动平均及清空尾差规则扣成本；差量为正时按原盘盈计价依据重新计算；均价方式在重建时无可用数量且需要盘盈价格时，明确报缺成本并暂停。用户已确认仓管补充该历史盘点单位成本，纳入同一纠错单的supplemental_count_costs，含count_line_id、unit_cost、提交人时间及预览版本；老板批准纠错时一并确认，不新增审批流程。保留原cost_mode，不静默改成manual；批准后保存该行当前有效补充值及所关联纠错审批，历史纠错JSON留前后值；后续重建仅在该时点仍无均价来源时使用已批准补充值。未经批准输入仅用于预览，禁止默认为0或套用今天均价。
   2026-10-13用户确认方向翻转：原账面0、实盘1、人工单价100的盘盈，经纠错成为账面2、均价80、实盘1时，改为盘亏1并扣成本80，不沿用原盘盈人工单价100。原人工输入与纠错前后结果保留供对比，不改实际观测和历史事件顺序。
8. 输出新的当前余额、有效流水计算值、订单成本毛利提成及差额清单。只改变计算结果，不再次发货、收款或发送外部消息。

每次涉及实际数量的变化检查历史在库不为负；当前最终受限合计不得超过在库。用户已确认历史占货区分：旧占货已经取消或减量且从未造成实际负库存，不重新否定已结束的旧占货。原入库100、占80后取消，采购纠正60可通过；实际曾出库80则仍拒绝。历史成本回放计算已发生事实，不重新提交旧订单进行可售校验。数量纠错影响当前占用时仍先用现有订单修改／取消或解锁处理，不自动裁决销售分配。

从期初重建可以扫描所有操作，只计算关联键；跨仓拆箱扩展关联键后处理其后续事件。分仓SKU均价彼此独立，没有拆箱关系不传播采购成本。保留按原数据重放的对照：没有纠错输入时，应能重建现有数量、成本和下单快照，否则报一致性错误，不能批准。

## 5. 确认与写回

无后续影响的纠错也走同一预览及重算函数，只是不要求老板审批；是否无影响由有关业务操作判断，不以余额数量相同判定。已有下单、拆箱、交付、盘点、破损处理等有关后续操作视为有影响。

有影响：仓管提交原因与修正输入→预览→有审批权限者确认（默认老板／管理员）；普通人员不能确认自己提交的纠错或盘点，老板例外保留，管理员身份本身不取消业务检查。无后续影响的直接更正不是待审批自批分支，由服务端判定影响并检查更正权限；不能由客户端自行声明无影响。预览无论是否差额0都展示相应事实变化；确认不能绕过校验。

批准持锁后核对申请版本、预览序号、目标单据版本及权限，重算并再次校验；任何错误回滚所有变化。对比写回库存、有效成本、订单计算及提成记录；收款金额未改变的采购成本纠错不撤销到账核对。

原已审核提成由纠错批准同步确认新金额；未首次计入订单仍等三条件，不自动计入。原已计入订单保留首次计入日期，对比上次正式金额生成差额；普通运费修改需重新复核，不借用纠错例外。

操作标识绑定用户、动作和规范化输入摘要，成功重试返回同结果，不再写入；同标识不同输入报冲突。批准失败不记录成功标识，可在问题处理后重新提交；已批准单据重复确认只能返回已批准结果。
