# 客户档案与第一版报表共识

## 客户档案

| 字段 | 已确定规则 |
| --- | --- |
| 姓名 | 必填 |
| 公司 | 选填 |
| 所属销售 | 销售创建默认本人；非销售代建必须明确选择所属销售 |
| 联系方式 | 必填文本，可填电话、微信等，不强制手机号格式 |
| 收货地址 | 至少一个；每个地址的收件人、联系电话、省份、城市、详细地址全部必填；电话按文本保存，不强制大陆手机号格式 |
| 别名 | 选填 |
| 备注1、备注2 | 选填；2026-10-09替代生日、兴趣、爱好 |
| 发票抬头、统一社会信用代码、电子邮箱 | 档案均选填，每客户一套；本单勾选开票时抬头必填，其余选填 |

- 2026-10-09用户明确取消生日、兴趣、爱好及生日提醒，替代此前个人开关/今天生日筛选规则；实现须删除相关字段、偏好、查询和页面逻辑，不保留隐藏功能。迁移及API变更方案待后端校准，当前应用尚未更新。
- 2026-10-09确认订单内新建客户：姓名、联系方式必填；快递订单收件人、电话、省市、详细地址必填并保存到档案。公司、备注、开票资料等选填为空不标档案不完整，不增加待补全逻辑；收件人不默认等于客户本人。
- 每客户一套开票资料，订单可选用或新填并同步客户；订单保存当次资料快照，客户后续修改不影响历史订单。勾选本单开票只要求抬头必填，信用代码/邮箱选填；财务与老板在线下开票，不增加税务接入或实际开票流程。
- 2026-10-09补充：散客不建档也不开票；旧兴趣/爱好迁入备注1/备注2，生日数据删除、提醒功能完全移除。历史操作记录的必要关联保留，不代表继续提供提醒功能。

- 客户状态通过归档等操作改变，不要求录入人员手填状态；底层仍需要保存状态以便识别正常及归档客户。
- 客户归档，不直接删除有业务关联的客户；历史订单保持关联。
- 门店散客仍允许不建立客户档案，上述必填规则适用于正式创建客户档案，不强迫每个散客留个人信息。
- 2026-10-03新决定替代此前不保存省市的规则：第一版仅支持中国大陆，每个收货地址保存省份、城市及手填详细地址；选择省份后选择对应城市，不增加区县选择器。省市属于地址，不属于客户的单一属性，支持多地址。
- 系统初始化省市基础列表，不要求员工逐个录入；后续按实际需要更新，不做自动同步或独立地区管理模块。订单保留省市及收货信息快照，客户地址变化不改历史订单。
- 同一客户向多个销售购买时，各销售分别维护自己的客户档案，不自动跨销售合并。姓名或联系方式相同不能作为跨销售全局唯一限制。
- 2026-10-03确认：销售创建客户默认归属本人；仓管、老板或管理员代建时必须明确选择所属销售，不默认归属非销售创建人。仅老板或管理员可变更归属，不增加转交审批；普通销售不能自行转交。变更影响后续客户维护及查看范围，不改变历史订单销售人员或提成归属，不自动合并同名客户。
- 不增加客户等级、积分或营销自动化功能。

## 四张报表

这里的“表”表示查询结果和展示页面，不表示数据库物理表。报表从订单、明细、单据、流水、库存余额、收款核对及提成等基础数据生成。

| 报表 | 筛选及内容 |
| --- | --- |
| 库存表 | 按仓库、IP、SKU 查询在库数量、可售数量、锁定数量及原因、破损数量、成本；分清订单占用、客户预留与囤货锁定，不重复扣减 |
| 销售表 | 按销售、客户、商品、渠道、周期统计金额、数量、毛利；实际销售默认按发货日期，未发货订单另行筛选，不混入已发货销售汇总 |
| 收款核对表 | 待核对、待处理、核对结果；订单金额、销售登记收款金额及差额、账户和凭证关联 |
| 提成表 | 预估、待复核、已计入及采购纠错前后金额和差额、补扣完成记录 |

- 不把四张报表强行设计为四张存储所有信息的数据库表，也不因此建立独立数据仓库或复杂 BI 平台。
- 不同售卖单位数量不能直接混加；金额、毛利按已确定的精确十进制和舍入规则汇总。
- 根据角色开关限定数据范围，商品及成本对所有人员一致展示；查看全部客户、订单、提成仍受权限控制。
- 收款登记金额不等于核实到账金额，预估提成不等于已正式计入提成，展示名称须明确。
- 2026-10-05确认Q07：收款核对报表按系统记录的首次登记收款凭证时间筛选；修改截图、金额或账户，以及重新核对均不改变该归属日期。实际收款时间仍选填，不作为周期归属。页面、API与Excel使用相同北京时间区间规则。
- 已计入后需重审的订单保留原计入日期及最后批准金额，新计算值另标待重审；再次通过后更新正式金额，保存前后差额和确认日期。原期间重查采用修正值，不新增月度封账或报表快照，已有Excel不自动改写。普通修改差额按重新批准日期展示，采购纠错差额按纠错批准日期展示，均不重复叠加到修正后的提成汇总；未首次计入的订单不能按此规则提前计入。
- 2026-10-03确认提成日期口径：预估及尚未正式计入的提成按订单正式提交日期；已计入提成按满足订单完成、到账核对通过、老板复核通过的正式计入日期；已计入提成的采购纠错差额按老板批准纠错日期，保留原计入日期。差额单独显示，不与修正后的提成重复相加，线下实际发放日期不作为统计口径。
- 2026-10-03确认：时间筛选为滚动近1个月、近3个月、近半年、近一年、全部及自定义起止日期。以查询当天为结束日期，开始日期分别向前推1、3、6、12个月，首尾当天均包含，按北京时间；页面及Excel显示实际起止日期。“1个季度”改为明确的“近3个月”，不按自然季度解释。时间范围不改变各报表统计日期口径。
- 门店现场交付完成时间作为相应出库销售日期，避免无需快递的零售遗漏；具体字段实现留到设计阶段。
- 销售表增加收货省份、城市筛选及分组，按订单实际收货地址快照统计销售地区；不增加第五张报表，不按客户当前地址追溯改历史地区。无收货地址的现场交付散客不猜测收货省市。
- 第一版只做以上四张报表，后续按实际需要增加；已有数据上的筛选、分组和汇总通常容易扩展，但未采集的事实无法从历史记录凭空恢复，不为假设的未来报表增加字段。
- 第一版 Excel 导出范围已确定为四张报表当前筛选结果，见 [期初与导出](INITIAL_DATA.md)。
