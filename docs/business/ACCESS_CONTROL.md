# 登录、角色与权限共识

## 最小登录

- 第一版支持账号密码登录，复用框架现成登录及安全密码存储。
- 不做公开注册、短信验证码、复杂权限规则引擎或多级审批。
- 权限由后端检查，隐藏界面按钮不能替代授权验证。

## 角色与权限开关

- 普通角色为销售、仓管／财务、老板，员工可兼任，权限取并集。
- 后台按角色为每个实际业务操作设置开关；不做个人权限覆盖，不为每个输入框设计权限。
- 提交与确认是不同操作，应分开设置，例如采购纠错提交和确认、盘点登记和确认。
- 老板及管理员可管理普通角色权限与员工普通角色；老板若要最高权限，可以同时拥有管理员身份。
- 只有管理员能授予或撤销管理员身份；管理员身份不受普通权限开关限制，不能通过普通角色开关取得管理员身份。
- 权限变化后后端按有效配置检查操作；必要记录包括修改人、修改内容和时间，不扩展完整操作审计平台。
- 第一版保持固定角色和预定义权限项，不增加自由规则表达式或任意数据过滤条件。

## 默认范围及开关目录方向

- 商品信息对所有人员一致展示，包括成本，不设置成本字段隐藏。
- 客户、订单及提成默认只查看本人范围；查看全部客户、查看全部订单、查看全部提成分别授权，兼任多个角色时按有效权限处理。
- 销售兼任仓管后拥有仓管全部权限，不另设简化仓管角色。
- 下列目录指导界面及 API 权限设计；默认开关见下方已确认配置，不把可查看直接等同于可修改。

| 权限组 | 预定义开关方向 |
| --- | --- |
| 基础资料 | 商品、仓库、供应商、收款账户维护分别设置 |
| 客户及订单 | 客户维护、订单创建及修改、取消、查看全部客户、查看全部订单分别设置 |
| 库存操作 | 采购入库、预留解锁、囤货管理、出库发货、拆箱、赠送分别设置 |
| 盘点 | 登记／提交、确认调整分别设置 |
| 采购纠错 | 提交、确认分别设置 |
| 收款及提成 | 收款核对、查看全部提成、提成复核、确认本人补扣完成分别设置 |
| 交付 | 确认收货、确认现场交付按实际操作分别设置 |
| 后台管理 | 员工管理、普通角色权限管理分别设置；管理员身份授予不由这些开关授权 |

- 收款核对仍遵守账户责任：对公由财务，老板私账由老板直接核对；权限开关不自动改变账户核对责任。
- 查看全部订单只扩大读取范围；维护他人订单须另有`change_all_sales_orders`及对应动作权限。登记他人订单收款须同时有`change_all_sales_orders`和`register_payment`；本人订单仍须有`register_payment`。
- 订单提成预估、正式核定金额及差额明细仅向该订单销售负责人、拥有`view_all_commissions`的人员及管理员显示。`view_all_sales_orders`本身不授予提成可见权；订单详情、列表、修改预览、页面及幂等重放均按当前权限过滤。
- 老板亲自提交采购纠错或盘点调整时允许自己确认，仍需保留提交及确认记录。
- 纠错／盘点审批按实际权限开关执行，默认由老板或管理员操作；普通人员被授予审批权限可审批其他人的记录，仍不能审批本人提交。老板自批是已确认例外；管理员权限不自动取消该业务检查。无后续影响的原单直接更正不进入待审批流程，不能把有影响更正伪装成该分支。
- 客户归属变更仅老板或管理员可操作，不开放普通销售自行转交，不增加转交审批；非销售代建客户必须明确选择所属销售。客户转交不改变历史订单销售人员及提成归属。
- 默认开关已于2026-10-03确认，账号初始化为上线前待办。普通人员即使取得审批权限，也不能确认自己提交的采购／期初纠错或盘点；角色开关不能绕过该限制。老板亲自提交允许自己确认并保留记录。客户归属变更权限已确定，不扩大为普通销售可操作开关。

- 表中成组操作仅为展示，各实际业务操作仍使用独立开关；查看全部不自动允许修改全部。
- 销售需要出货时兼任仓管，取得仓管权限；仓管从订单收货信息安排发货，不默认开放全部客户档案。
- 对公到账由财务核对，私账由老板核对；老板兼任财务时可核对对公，不能因查看全部或角色管理权限取得私账核对责任。
- 销售可确认本人提成补扣完成；管理员具有全部业务权限，但不能绕过业务校验，管理员身份仅管理员可授予或撤销。
- 仓管代建客户默认开启，但必须指定有效销售负责人；该权限不授予查看全部客户或替他人维护全部客户。
- 后续老板或管理员可以调整普通权限开关，仍遵守客户归属变更、管理员身份及账户核对等已确认边界。

## 管理员与业务约束

- 管理员是超级角色，具有全部业务权限及权限管理能力。
- 超级权限不跳过业务完整性规则：不能超卖或产生负库存、缺采购价正式入库、跳过必填收款截图、直接改库存余额。
- 收款问题暂停出库、纠错重算和必要审批记录等要求仍适用，不因管理员身份抹去。
- 不开发管理员绕过校验的后门。

## 最小验收方向

1. 员工兼任角色取得并集权限，未获授权的 API 请求被拒绝。
2. 普通开关不能授予管理员身份，非管理员不能修改管理员身份。
3. 老板和管理员能管理普通权限；管理员不受开关关闭限制，但仍受业务校验约束。
4. 无查看全部客户／订单权限时不能访问其他销售客户／订单；订单查看范围不等同于维护范围，商品成本对所有用户一致展示。
5. 他人订单收款要求查看范围、`change_all_sales_orders`及`register_payment`；撤权后的新请求与幂等重放均拒绝且不产生业务副作用。
6. 订单提成只向本人、`view_all_commissions`或管理员显示；列表、详情、页面和提成复核响应一致按当前权限过滤。
7. 老板自提交自确认有记录，权限变更保留修改记录。
