# 销售订单、收款核对与履约共识

> **2026-10-20成本口径：** 本文已按实际出库成本及独立提成差额确认规则校准。本轮应用 `6024205` 已完成分项QA/UI、现场/快递网页链及负责人限定验收，证据见[发布记录](../project/RELEASE_COST_WORKFLOW_20261020.md)；已部署版仍为 `71cf9f6`/0015。新单实际出库计成本，既存旧单保留快照，不将代码验收当正式业务切换。

## 下单与占货

- 2026-10-09增量：订单内可新建客户，姓名必填、客户联系方式选填（2026-10-22更新），快递必需收货信息保存到档案；客户与订单确认共同成功或回滚，不先生成孤立客户。选填信息缺失不标待补全。
- 本单可登记开票需求，仅关联客户的订单支持；散客不建档且不开票。客户一套资料，勾选开票仅抬头必填，代码/邮箱选填；订单快照及新填客户同步不改历史订单，由财务/老板在线下开票。具体字段/API待技术增量校准，不改变成交、收款和提成规则。

- 一单支持多个 SKU，销售手动选择各供货仓库、数量、成交单价、客户或散客及销售渠道。
- 正式提交时检查可售数量并原子占货，库存不足明确提示，重复提交不得重复占货。
- 新单下单仅检查并占货，展示所选仓库SKU当前成本参考，不固定正式成本、不显示毛利或提成。实际发货或现场交付时，以同事务库存实际扣减成本确定订单成本。
- 成本参考显示3位但不参与反推正式成本；同仓SKU实际扣减金额按数量分摊至稳定订单行，末行承接尾差，明细合计必须等于库存流水扣减。既存旧单保留旧快照口径，不因迁移批量改算。
- 实际出库后毛利＝订单收入－实际出库成本－出库运费；提成＝整单毛利×10%并保存3位。后续普通采购不改已出库订单；已批准历史成本纠错可重算经营结果，但核定提成须独立确认。
- 客户预留在线下沟通，由仓管先解锁为公共可售，销售再下单，不做指定订单放行。
- 未发货修改同步处理占货和金额，与已收款金额不符时提醒人工处理。
- 所有未发货订单取消统一释放占货、恢复可售；保留已收款凭证，取消不自动表示退款，需要预留时由仓管人工锁回。
- 已发货不直接修改商品、数量或供货仓库。

## 订单修改与重新核对

| 修改内容 | 已确认处理规则 |
| --- | --- |
| 仅减少数量 | 释放减少部分占货、更新收入；新单仍未形成正式成本 |
| 增加数量、换 SKU 或换仓库 | 整单重新检查并原子更新占货及金额；新单仅更新当前成本参考，不重锁正式成本或预估提成 |
| 修改成交价 | 未出库更新收入，新单成本／毛利／提成仍未形成；已发货商品数量等不能直接修改 |
| 修改订单金额、收款账户或截图 | 原收款核对结果失效，需对应账户核对人员重新核对 |
| 修改收货地址或备注 | 不影响成本、提成或收款核对；已发货地址不能直接改写成新的实际发货地址 |
| 修改影响已复核提成的数据 | 老板提成复核失效，需重新复核；采购纠错仍使用采购纠错审批与重算流程 |

- 采购纠错生效只更新库存及经营计算，保留已核定提成。老板／超级管理员之后独立选择调整或保持，系统以当前有效核定额计算差额并留原记录；不得把库存纠错批准当作提成差额批准。未核定订单仍走正常流程。

- 多种修改同时发生时，适用所有有关规则；增加数量、换 SKU 或换仓库仍整单检查占货。旧口径订单修改继续原快照规则，新单不固定成本。
- 修改整体成功或整体失败；重新检查时考虑本订单已有占货，不能先释放到公共可售再尝试抢回，失败保持原订单、占用和核对结果。
- 收款核对或提成复核失效不会倒退已发生的发货、收货事实。
- 因核对问题已经暂停出库的订单，修改后仍须核对通过才能解除暂停，不能用修改来绕过暂停。

## 收款登记与快速发货

- 销售选择具体收款账户（银行、微信、支付宝等），填写销售登记收款金额并上传截图；收款时间选填。
- 截图必填，未提交凭证不能进入待出库。
- 一单可上传多张凭证图片，至少一张；类型JPEG、PNG、WebP，单张最多10MB，不支持PDF、OCR或自动压缩，查看沿用订单权限，不改变一单一笔付款的限制。
- 系统直接比较手填收款金额与订单金额，无需 OCR；金额不一致时提醒并要求填写原因，确认后允许继续发货。
- 上传截图及金额一致均不等于核实实际到账，第一版不做 OCR、截图自动审核或支付渠道接入。
- 尚未核对时允许发货，到账后置核对；但核对人员已发现问题且尚未发货时，暂停出库。
- 待处理问题由销售补充凭证或处理差额，再由对应核对人员核实；暂停不能仅凭销售改信息自动解除，实际恢复条件需核对通过。
- 履约状态与收款核对状态分别记录，核对问题不改变已发货或已完成的履约事实。

## 到账核对与提成

- 对公银行转账由财务核对。
- 老板私人微信、支付宝账户由老板直接完成到账核对，不再要求财务重复确认该账户到账。
- 发现凭证或金额问题时，标记待处理并填写原因；未发货暂停出库，已发货保持发货状态。
- 对应账户核对人员确认通过，作为提成所需的收款核对通过条件；不因使用私账取消老板的提成复核。
- 正式计入提成必须同时满足：订单完成、收款核对通过、老板提成复核通过。
- 已计入后因普通修改需要重审时，保留原计入日期和最后批准金额，新金额标记待重审；重新通过后更新正式金额并记录前后差额及确认日期，不重新生成首次计入日期。保留旧批准金额不表示新金额已经通过。差额线下处理，不重复加入修正后汇总。
- 提成按订单毛利的 10% 计算，销售出库运费扣毛利，亏本提成为负，退货不扣提成。补扣资金在线下处理。

## 发货与现场交付

- 快递流程：待确认（已占货）→ 提交收款凭证并确认 → 待出库 → 确认发货 → 待收货 → 销售确认收货 → 已完成。
- 仓管或有出货权限的销售操作发货；选择承运方，提供运输编号，关联订单已选定的出货仓库。
- 承运方先支持跨越、顺丰、货拉拉；跨越和顺丰填写运单号，货拉拉填写平台订单号。
- 一单可有多个运输编号、对应多个出货仓库，不重新选择或擅自改变订单供货仓库。
- 暂不支持分批发货，一次确认整单发货；确认时扣在库数量、解除对应订单占用，不能重复扣减。
- 出库运费默认 0，人工分摊，不改变剩余库存成本。
- 已确认运费录入时点：下单运费默认0但不预计算毛利提成；确认发货／现场交付时填写已知运费、重算毛利及预估提成，未知仍可按0继续出货并后续补填。运费更改只更新本单毛利及提成，不改商品或剩余库存成本；原提成已复核则失效，由老板重新复核，线下补扣仍人工处理。不增加运费支付管理。
- 门店现场交付无需承运方或运输编号；满足收款凭证及无暂停出库问题的要求，实际交付后确认完成，同时扣库存。
- 快递订单由销售确认收货后完成，不做物流自动查询或自动确认收货。

## 金额精度

- 数据库金额保存到小数点后 3 位，包括实际业务金额及保存的单位成本、提成金额等；使用精确十进制，不使用二进制浮点保存金额。
- 计算过程使用高精度十进制，不反复提前舍入；保存金额结果时统一四舍五入到 3 位，正负金额规则相同（半值远离零，例如 1.2345 → 1.235，-1.2345 → -1.235）。具体计算精度和金额字段容量在实现设计时确定。
- 明细金额先计算并保存，再汇总订单金额，确保展示明细之和等于订单总额。
- 整单毛利 = 明细成交金额合计 - 明细成本金额合计 - 本单销售出库运费；整单提成 = 整单毛利 × 10%，最后保存到 3 位，不逐条舍入提成后相加。
- 对外实际支付、退款或补扣在线下执行，不因数据库精度扩展支付功能。

## 最小验收场景

1. 正式提交并发占货不超卖，重复提交不重复占货。
2. 缺收款截图不能进入待出库；收款时间未填不阻塞。
3. 金额不一致必须提示并填写原因，确认后可发货，但不自动通过收款核对。
4. 未核对可发货；已发现收款问题且未发货时，快递和现场交付均暂停。
5. 发现收款问题时已发货，保留发货状态并阻止正式计入提成。
6. 老板直接核对私账到账，对公由财务核对；提成仍需订单完成及老板复核。
7. 多仓物流编号正确关联；货拉拉平台订单号可用，现场交付不要求物流信息。
8. 金额可精确保存 3 位；1.2345 舍入为 1.235，-1.2345 为 -1.235；两条明细各毛利 0.005 时，整单毛利 0.010，提成为 0.001，不得逐条舍入后合计为 0.002。
9. 仅减量保留原成本；增量或换货换仓整单取当前成本，修改前明确展示变化。
10. 金额、账户或截图变化使原收款核对失效；影响提成的修改使原提成复核失效；地址、备注修改不误触发重审。
11. 修改占货失败时保持原订单及库存占用，不能因先释放库存导致货物丢失。

## 2026-10-23用户确认：按本单职责展示操作

首页优先展示本人待处理事项；订单动作以当前用户在该单的职责与实际状态决定，不将所有有权限的表单平铺。老板仍可销售，但对其他销售负责的订单不提供销售登记收款/出货的代改入口；核对/审批不通过退回原负责人员修改并重新提交。现有收款待处理、未发货暂停及已发货事实不倒退等规则保持；各审核类型的重提条件不得据此自行合并或新增。所有具备仓管职责及相应权限的人员均可见待发货并实际处理，暂不引入个人指派。当前仅批准设计方向，具体界面待原型批准，服务端实施与权限校准另行验收。

随后用户明确：老板若兼任仓管，也可处理他人销售订单的共享发货及该次运费；老板身份本身不赋予销售代改职责，其他销售的收款登记、订单修改仍由原销售负责。身份采用已有职责能力叠加，管理员超权限保留；动作还须满足可见范围、单据归属及当前业务条件。具体v2已在UI会话批准开发，实现及权限仍需独立验收。
