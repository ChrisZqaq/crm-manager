# 采购入库模块共识

本文件记录采购入库讨论形成的业务共识。数据库、接口及重算执行方案见待确认草案；文末列出的未定事项不得自行推定。

## 范围与流程

- 系统从实际到货、清点入库开始管理。
- 客户需求收集、官方订货、第三方调货协商、提前收款及到货数量分配在线下完成，不建立未到货订单、采购订单、需求配额或自动配货系统。
- 销售按线下最终分配的数量在系统下单，关联实际收款凭证；系统不负责计算原需求不足产生的退款。
- 官方进价由官方确定，第三方进价由老板提供；通常由仓管兼财务清点、录入。
- 流程：实际到货 → 清点 → 填写入库单 → 确认入库 → 更新库存及成本，同时处理本次预留和破损数量。

## 单据内容

| 范围 | 信息与约束 |
| --- | --- |
| 单据 | 一个供应商、一个仓库；供应商名称必须记录 |
| 明细 | SKU、实收数量、采购单价、分摊采购运费、客户预留数量、破损待处理数量 |
| 凭证 | 选填，建议提供官方送货单照片或第三方渠道截图、付款截图 |
| 运费 | 默认 0，人工分摊到明细，计入商品库存成本，不管理采购运费是否付款 |
| 采购价 | 确认入库前必须填齐，不能用缺失值或默认零代替未录入的价格 |

- 实收数量必须为正整数，包含正常和破损货；采购单价和运费不能为负。破损数量不超过实收总量，客户预留等正常货受限数量合计不超过实收数量减破损数量，同一件货不能重复计入不同限制。
- 凭证仅支持JPEG、PNG、WebP图片，单张最多10MB，可多张，仍选填；不支持PDF、OCR或自动压缩，访问遵守入库单权限。
- 已确认真正的零采购价允许入库，确认摘要明确提示“零采购价，请核对”；空价格仍不能确认，不自动按0处理。有分摊采购运费时照常计入库存成本，不增加赠品采购模块或额外审批。
- 2026-10-03确认：第一版用统一入库核对摘要替代自动判断数量或金额过大的提醒。确认前展示仓库、供应商及每行SKU、单位、数量、采购单价、分摊运费和成本金额，人员核对后确认；保留正整数、非负金额、采购价必填、受限数量不超量等硬校验。不增加异常大值阈值配置、历史价格比较或任意业务硬上限，不混加不同单位的数量。
- 同一入库单多仓到货时，分别录单，不增加单内跨仓拆分功能。
- 入库明细提供可选预警阈值输入框，留空使用全局默认值，另提供关闭该SKU提醒按钮；全局默认初始为5，后台可全局关闭提醒并保留配置。SKU设置作用于该SKU所有仓库，各仓按各自可售数量判断，不针对入库批次单独提醒。再次入库留空按同一规则使用默认值，不隐含保留旧专用阈值；关闭与恢复的交互细节在页面设计中明确。
- 供应商档案形式、单据日期、编号和具体字段类型在数据库设计阶段确定。

## 仓库与物流站点

- 仓库维护名称和地址，入库时选择。
- 物流站点可作为仓库，例如“上海物流站点”；确认实际到货和数量后正常入库，转寄后正常销售出库。
- 物流站点货物由仓管及相关销售共同核实实收数量、采购价，能提供送货单及客户物流单号。
- 不增加单独的转寄业务系统，不因供应商通知已发货就增加实际库存。

## 库存与移动平均成本

- 官方、第三方及物流站点统一使用同一种成本规则。
- 每个仓库＋SKU 独立计算移动加权平均成本。
- 本次入库成本金额 = 实收数量 × 采购单价 + 分摊采购运费。
- 入库后平均成本 =（原剩余库存成本金额 + 本次入库成本金额）/ 入库后在库数量。
- 客户预留、订单占用、囤货和已购入的破损货均属于在库库存并保留成本；破损货不可售。
- 可售数量 = 在库数量 - 订单占用 - 客户预留 - 囤货锁定 - 破损待处理数量；这些受限数量不得重复扣减同一件货。
- 正常且未锁定的货在入库确认后立即可售。
- 库存和成本更新必须一起成功或一起失败，重复确认不得重复入库。
- 后续普通采购入库不自动修改已固定的历史订单成本；明确批准的采购纠错是例外。
- 订单成本与库存出库成本分别保存：订单毛利及提成按下单成本，实际库存金额按发货或现场交付时的移动平均成本扣减；每次扣减保存3位，清空时扣完剩余成本，不更改已固定的订单成本或提成。已确认破损退款采用处理时的移动平均成本扣减，见 [SPEC](SPEC.md)。

## 客户预留与人工解锁

- 入库时可以人工填写客户预留数量，不记录线下的原始需求或自动比例分配。
- 示例：实收正常货 60 箱，预留 50 箱；确认后在库 60、客户预留 50、可售 10。
- 入库和预留一次完成，不能先让全部货物可售再补锁定。
- 客户预留与主动囤货区分原因；不建立独立的销售配额系统。
- 销售与仓管在线下沟通实际需要下单的数量，由仓管人工解锁相应预留，恢复为公共可售库存，销售随后正常下单。
- 示例：在库 60、预留 50、可售 10；解锁 20 后预留 30、可售 30；销售成功下单 20 后订单占用 20、可售 10。
- 第一版明确接受解锁至下单期间其他销售可能使用这部分库存的情况，不做指定销售保护或解锁与下单的原子转移。
- 下单仍检查可售数量并原子占货，库存不足时提示，不因人工解锁而绕过防超卖及防重复提交校验。
- 所有订单统一在正式提交占货时按各供货仓库当前平均成本固定成本，并预计算提成。
- 不做订单待放行状态、指定订单放行审批、订单预留来源追踪或混合来源订单分支；不做自动到期释放。
- 所有未发货订单取消后统一释放订单占用、恢复可售；需要继续预留时由仓管人工锁回，不追踪原预留来源，不自动退回预留。

## 破损与换货退款

- 清点时登记破损待处理数量，不分配、不销售，保留采购成本。
- 仓管在线下完成换货或退款；第一版不做完整售后申请和物流跟踪。
- 正常替换货实际到达并确认后，记录处理结果，恢复对应正常可售数量，不能重复增加数量或总成本。
- 2026-10-03确认：破损退款在处理时减少对应在库及破损数量，按当时移动平均成本扣库存，清空时扣完剩余成本；不修改或删除原入库单，不重算历史订单及提成。此前“少采购对应数量”的说法以本规则为准，实际原单录错才走采购纠错。
- 处理记录分别保存库存扣减成本、实际退款金额及差额，差额不摊给剩余商品或销售提成。
- 退款后即使破损实物留在公司，也不纳入本系统管理库存，不恢复可售；其后续使用或处置在线下完成。
- 破损退款中未退还的采购运费记录为本次采购损失，不摊给其他商品，不影响其他订单提成，不默认全部费用均已退回。
- 示例：对应一箱采购价 100、分摊运费 5，供应商只退款 100；对应货物退出系统库存，未退运费 5 记采购损失。损失金额随该退款处理记录，不扩展完整财务系统。
- 金额采用高精度十进制计算，保存结果时统一四舍五入到 3 位，明细金额先保存再汇总；规则见 [销售履约](SALES_FULFILLMENT.md)。

## 入库纠错与审批

- 未影响后续业务的错误允许修改，修改后统一调整相关库存和成本。
- 已影响后续业务的错误，由仓管提交、老板确认后生效；待审批期间原数据继续有效，拒绝不改变原数据。
- 确认前展示受影响的库存、订单成本和提成变化。影响范围包括成本流经拆箱等业务后的关联数据，不能只重算当前仓库余额；同仓或跨仓拆箱均沿实际来源及目标关系重算，第一版不做保持SKU不变的独立仓库间调拨。
- 采购纠错可以重算受影响的库存成本和订单提成，包括已审核、已计入的提成。
- 2026-10-03确认：老板批准纠错时，一并确认影响清单中原已审核提成的新金额，不要求逐单重复审核；保留前后值、差额及审批依据。尚未审核订单仍走正常提成流程，纠错审批不自动将其计入。
- 对已实际发放提成，展示修改前、修改后和差额；补发或扣回在线下执行，销售完成后自行点击完成。本系统不执行资金转移，完成后以纠正数值作为后续依据，保留差额对比及完成记录。
- 审批及执行时必须保证确认的修改内容和影响结果仍然有效；并发操作不能造成部分更新或未经确认的结果生效，具体实现待设计。
- 重算必须完整成功或完整失败，失败时保持原有效数据并明确反馈。
- 2026-10-03确认：按业务在系统中实际生效的先后顺序重算，不按人工填写的单据日期重新排序；沿拆箱等实际成本流转关系传播影响，不能把后续入库成本倒算到此前下单时点。
- 最小审批记录保留纠错原因、前后值、提交人、确认人、时间和结果；这不扩展为完整操作历史审计。
- 基础校验不能因老板确认而跳过。2026-10-03确认：数量纠错导致库存不足覆盖占用及锁定时，提示缺口及相关记录，先人工通过现有订单修改／取消、预留／囤货解锁处理，再由老板审批；不自动分配或增加一键联动。订单数量与占用同步变更，金额变化沿用收款重新核对规则，审批时再次校验。
- 纠错及重算后库存不能为负；若导致当前余额或受影响历史时点出现负库存，阻止修改生效，提示核对相关入出库单据，保持原数据有效。不增加专门的异常处理流程。

## 最简单的登录和身份区分

- 第一版使用账号密码登录和后端角色权限，替代此前“暂不做鉴权”的原型设想。
- 最小角色方向：销售、仓管／财务、老板；账号可以兼任，销售需要出货权限时可兼任仓管。
- 老板负责受影响采购纠错确认，不能仅靠同一个人连续点击两个确认框代替审批。
- 优先复用框架现成登录与安全密码存储，不做注册、短信验证码、复杂权限规则引擎和多级审批。
- 按角色配置业务权限开关，管理员超级权限及普通权限管理规则见 [登录与权限](ACCESS_CONTROL.md)。老板亲自提交纠错或盘点调整可自行确认并保留记录；账号初始化与最终默认开关在设计时落实。
- 新增或调整诊断日志、埋点仍需事先与用户确认，遵循 [协作规则](../AGENTS.md)。

## 最小验收场景

1. 普通到货入库，含人工分摊运费，库存及移动平均成本正确。
2. 入库 60、预留 50、可售 10；仓管解锁 20 后预留 30、可售 30；销售下单 20 后占用 20、可售 10。
3. 多个销售并发占货不超卖，重复确认不重复入库、占货或扣库存。
4. 所有未发货订单取消后恢复可售，不自动退回预留；仓管可按需人工重新锁定。
5. 破损货计成本但不可售，换货不重复增加库存或成本。
6. 未填价格、负数、数量不合法及超量预留不能确认入库。
7. 仓管不能自行生效需老板确认的纠错；批准后库存、成本及已审核提成一致更新，失败不留部分结果。
8. 普通新采购不改变已固定历史订单成本。
9. 数量纠错导致负库存时拒绝生效、提示核对，原库存及成本保持不变；老板确认不能绕过此校验。

## 待确认边界

- 占用及锁定缺口先通过现有操作人工处理、再审批已确认；不增独立联动修改模式，历史非负库存校验仍保留。
- 破损退款按处理时的移动平均成本扣减已确认，不触发历史重算；采购纠错按系统实际生效顺序重算已确认，具体实现算法仍待细化，不将未退运费损失重复分摊。
- 高精度十进制计算的具体精度及字段容量、业务影响判断及重算实现尚待设计；入库前核对摘要替代异常大值提醒、按系统实际生效顺序重算、保存3位及四舍五入规则已确定。

以上未定事项不妨碍保存已确认规则，但实施相应行为前必须明确，不据此自行添加功能。
