## 手机与键盘验收点（固定版后定向实测）

1. 1280/390、米/绿必要相邻：根无横溢；390弹窗宽度沿用客户`100vw−24px`、最大高`100dvh−24px`并内部滚动，标题/关闭、凭证及提交都可达；表格只在自身容器横滚。12位业务单号可辨，不压成“订单2…”；表单和明细长文正常换行。
2. 鼠标点行空白、键盘聚焦行Enter/Space、明确“查看/处理”按钮均仅打开一次同一记录；焦点可见。行内a/button/input/select/textarea等交互控件的点击和冒泡键盘事件不能触发行级打开；空格不滚背景、Enter不重复开窗，任何打开操作不产生业务POST。不能原样复制客户现有仅排除button的委托作为全覆盖保证。
3. 原生dialog有可见标题及aria-labelledby；开窗焦点进入、Tab/Shift+Tab留在窗内，Esc/关闭按既有未保存输入保护处理，关闭后回原触发按钮/行，筛选/页码/列表位置保持；若提交后当前行被筛掉，焦点回列表稳定位置。凭证放大/查看不叠出无出口的模态层。
4. 原因字段隐藏时无残留空位、必填阻断或Tab落点；异常展开与选择框相邻，标签常见、错误就近且可读。通过→待处理→通过→待处理与等额→差额→等额→差额测试草稿保留及条件required切换。字段显示无需额外说明段落或强制动画，遵守既有减弱动态。
5. “其他操作/调整运费”用键盘可展开/收起，目标至少44px；默认不抢当前任务，不把收起动作当作清空。收货首屏无第二套运费编辑；任务深链仍定位实际当前动作。
6. 连续合成链：创建→收款→核对→出库→收货每一步单号不变；实际点提交验证禁用、失败留值、成功最新状态/下一步、完成动作消失、收货返回待办。双击/Enter重复触发不重复写入，旧版本冲突有可执行恢复；这部分由QA负责业务真实写操作，UI固定版只作授权范围的定向视觉/键盘复核。
