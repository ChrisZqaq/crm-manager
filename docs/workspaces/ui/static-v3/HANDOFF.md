# UI-STATIC-6 前端实施交付

交付日期：2026-10-08。批准事实唯一见[UI WORK审批栏](../WORK.md#唯一审批栏)。本文件说明获批三张静态图的六页设计如何实施，图片指纹及提示词见[README](README.md)。图片冻结，后续修改另存版本。

## 交付范围与依据

本轮六页：工作台、销售订单列表、库存查询、商品档案、客户列表及详情面板、收款核对列表及详情面板。实施其共同导航、页面外壳、表格、筛选、状态标签和关联现有业务操作。v1/v2 HTML不是本轮批准来源。

图片确定视觉和布局；字段、数据、权限、状态、计算、分页、导出及提交协议按现有获批业务规格和实现。图中的缩写、遗漏、示例金额、状态或新增字段不产生新业务授权。实施前核对真实页面、消费者与共享工具。负责人登记本轮前端为应用写入者并安排接口依赖；UI不改应用文件。

## 六页布局和内容

1. **工作台**：[图1左](01-dashboard-orders.png)。标题与新建订单主操作；四个紧凑摘要；左侧待办订单列表，右侧待处理事项/低库存提醒，底部轻量销售趋势。摘要与趋势仅接入现有授权范围内的真实查询，沿用已确认报表口径，并在标题/说明体现实际口径及时区。不得新增“今日销售额”计算规则、跨用户数据权限或假数字。缺少数据来源由前端报告UI及负责人，安排最小依赖，不自行在浏览器推算业务统计。
2. **销售订单**：[图1右](01-dashboard-orders.png)。标题/新建订单、状态标签、搜索和仓库/销售/日期筛选、订单表与分页。履约状态与收款核对状态分列；列包含订单编号、客户/散客、销售、出货仓库、金额、履约、核对、操作。展示多仓订单时按现有真实数据表示，不把整单强行归一个仓库。待确认/待出库/待收货/已完成等名称沿用现有状态定义，取消与异常状态也保留。查看/新建等链接连接现有真实流程。
3. **库存查询**：[图2左](02-inventory-products.png)。摘要、商品/SKU/IP/仓库/状态筛选、导出、库存表。每行明确SKU、单位及仓库，订单占用、客户预留、可售等概念分别呈现；缺省、锁定及破损的实际口径沿用既有实现。摘要不能直接相加箱/盒/包/个的数量；不同单位分别显示或使用已有正确统计。单位成本依规格显示三位小数，金额和数量对齐。低库存标记遵守既有提醒设置及权限。
4. **商品档案**：[图2右](02-inventory-products.png)。IP分类、搜索/类型/状态筛选、商品表、选中商品资料及独立SKU区域。产品语言/官方编号等共有信息与SKU分开，保留IP→可选系列→产品→SKU结构；类型沿用补充包/周边/礼盒·预组，SKU沿用真实编号和单位，不做自动换算。缩略图只复用已存在图片能力，没有图片数据时用统一占位图；不新增上传/生成产品图片功能。图中复制/删除动作不能凭图新增；复用现有编辑、停用及关联数据保护。
5. **客户**：[图3左](03-customers-payments.png)。我的/全部客户范围、搜索与销售筛选、今天生日入口、客户表、右侧客户详情。全部范围和生日入口按既有权限/个人提醒设置展示。详情含基本资料、收货地址、最近订单；真实必填联系方式、收件人、电话、省市和详细地址不能因图片简化而省略。图中客户类型标签没有规格依据，不增加此字段。复用已有地址与归属维护规则。
6. **收款核对**：[图3右](03-customers-payments.png)。待核对/已通过/待处理筛选、账户/日期/搜索、列表、选中订单右侧详情。列表和详情清楚区分订单金额、登记金额/差额、收款账户、履约和核对状态。保留真实凭证权限及查看；上传截图不等于已核对。凭证上传及金额/账户编辑只在已有角色和状态允许的入口展示，不默认给核对人员新增权限。结果/原因/确认控件调用现有核对流程，不实现自动识别。日期按既有首次登记凭证时间口径，不能照抄图片的日期含义。

## 操作与响应式要求

- 商品状态已决（2026-10-08，用户直接确认，来源见UI WORK）：商品档案“状态”按SKU启用/停用筛选，标签明确为“SKU状态”，选项全部/启用/停用；档案列表和详情可查看停用SKU，清楚标注状态。下单选品继续遵守现有规则；不把档案可查看停用SKU解释为可以下单，不新增产品停用规则。相关API扩展及写入安排由负责人协调，权限仍沿用既有档案访问权限。
- SKU筛选联动澄清：启用/停用选择作用于SKU，不按Product状态过滤。产品主列表只保留至少一个匹配SKU的产品；行内SKU和选中产品右侧SKU子表只显示匹配项，产品共有资料正常显示。选择全部时显示两类SKU并各自标注状态。子表明确当前SKU状态筛选，不能把筛后子集标成该产品完整SKU集合；查看全部规格时使用已有“全部”筛选，不新增第二套状态开关。若切换筛选后原选中产品不再匹配，关闭其详情并清除选择，不显示上次结果。
- 顶栏控件澄清（2026-10-08）：只接入已有当前页能力，不新增跨模块搜索或全局仓库状态。同页优先保留列表上方一套实际筛选；顶栏保留面包屑/账号，可显示只读范围说明，没有对应能力的搜索/下拉不展示成可操作控件。仓库筛选只影响当前适用页面，不跨模块持久生效。收款q在授权收款记录中匹配既有订单标识和既有客户展示名（已有快照口径则沿用快照），不新增关联取值规则或其它搜索字段。
- 收款搜索澄清（2026-10-08）：获批图3右侧列表筛选框文案为“搜索订单编号、客户名称”。因此范围是现有系统对外展示的订单编号/ID或订单关联的客户名称；沿用现有标识，不新增SO格式编号字段，不扩展到联系方式、SKU或全局客户检索。仅在当前收款核对页面的授权数据范围内查询，匹配方式沿用既有服务端搜索约定；与账户/日期/核对状态筛选共同生效。销售选择控件使用名称下拉，内部ID仅作为接口值，不让店员输入ID，不新增用户管理功能。
- 2026-10-08负责人转达用户已确认：订单列表日期筛选=下单日期，销售报表仍=发货/现场交付日；工作台所有登录人员可进入，各数据块沿用现有权限，不增加工作台权限开关，仅展示既有业务待办，不新增客户跟进功能。业务/API公共文档为规则依据；不重复询问。当前后端补最小接口，前端停写，负责人发布固定接口并恢复前端后接入。
- 复用Django既有模板、session/CSRF、分页50/200及授权查询；订单preview→用户确认POST、operation_key/preview_token和服务器最终校验保留。无必要框架或依赖新增；公共样式只抽取这批页面实际复用的部分。
- 筛选保留已选值和现有分页行为，错误保留输入并明确指向字段；处理加载/提交中/成功/失败状态，防重复点击不能替代服务端幂等。已有后端返回的错误及请求ID正常展示。
- 空列表、无结果、权限不足、接口失败均提供具体文字及合适返回/重试入口，避免误显示为零值。权限不足的数据不渲染到页面再隐藏。
- 桌面详情面板保留列表上下文，明确关闭入口；窄屏改为同页全宽详情区或既有详情页，返回后保持筛选和选择。侧栏变为可开关菜单，筛选换行，宽表格在自身容器横向滚动，主页面不横溢。手机为同一设计的响应式适配，未批准另做移动端视觉主题。
- 所有实际操作仍走既有业务确认及状态保护，不使用拖拽改变订单状态，不仅凭颜色显示核对结果。

## 验收与问题路由

前端核对三张图指纹及唯一审批记录，按负责人指定范围实现，自检六页的布局、真实筛选/详情/分页/原有业务入口、空/错误状态、权限及桌面/窄屏。图中的示例数据不用于真实计算验收。交付固定版本、自检证据、涉及文件及未测项，发QA并同步负责人，然后停止应用写入；整体测试与负责人验收沿用协作规则。

前端遇到设计/交互不明确处直接问UI；UI在已批准视觉和既有规格内澄清并记录。接口事实可直接问后端，跨后端改动同步负责人排期。UI无法决定的设计取舍、新业务规则或会影响库存/成本/收款/提成/权限的未知项，报告用户并同步负责人，只暂停依赖部分。不得用默认方案绕过尚未确认规则。
