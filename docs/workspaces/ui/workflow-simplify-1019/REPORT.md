## 1. 结论

已有基本链路及统一主题可继续复用。值得减少的是找入口、找字段和反复选择的负担；需要保留的是每次改变库存、收款事实和提成的明确确认。第一轮建议做选择器合并、按状态突出当前动作、采购/调整按任务展开；不做工作流引擎/新业务状态，不引入OCR、支付接入或批量审批。

本轮确认订单内建客、已有地址复用、现场模式隐藏快递地址、开票按需展开、登记金额按订单预填、默认运费0均已存在，不把它们重复报为新增功能。来源：订单表单/详情源码和当前订单表单观察。

## 3. 当前全系统人工动作清单

动作按业务意义分组，不按点击/字段数量计数；不是每张订单都要做所有异常操作。角色为现行默认职责，实际权限及本人范围仍由服务器决定。

| ID | 任务/责任人 | 当前需要人做什么 | 系统已做/不能省的事实 |
| --- | --- | --- | --- |
| A01 | 登录/各人员 | 登录后看本人可用入口、待办 | 不新增角色或扩大权限 |
| A02 | 查商品/销售仓管 | 搜商品/别名/条码，确认语言、单位/包型及对应SKU | 歧义须人选；不同单位不换算 |
| A03 | 查库存/销售仓管 | 选择仓SKU看可售/在库/限制、必要时筛选导出 | 不能拿在库当可售、不能手改余额 |
| A04 | 建单/销售 | 选已有客户/本单新客/散客、渠道及快递/现场 | 订单内建客已有，不必先跑客户页 |
| A05 | 地址/销售 | 快递选既有地址或填收件人/联系方式/省市/详址 | 现场免地址；快照不跟随档案变更 |
| A06 | 选货报价/销售 | 每行SKU、仓库、数量、成交单价；按需加行 | 没有参考售价；数量/成本/金额服务端校验 |
| A07 | 开票/销售 | 有需求才勾选并核抬头，代码邮箱可选；写备注 | 仅记录需求，散客无开票；不实际开票 |
| A08 | 确认下单/销售 | 看预览→确认并占货 | 当前两次有意义确认，保金额/成本、版本/并发校验 |
| A09 | 登记收款/销售 | 选实际账户、核金额、上传至少1图；差额填原因，时间可选 | 金额已预填；登记不是到账核实 |
| A10 | 快递出库/有发货权限者 | 实物打包，填承运方/编号及对应供货仓，必要运费，确认整单发货 | 整单一次、凭证有效且未暂停、扣在库及释放占用 |
| A11 | 现场交付/有权限者 | 实际交货后确认，必要运费 | 无物流；不能因为现场就免凭证/暂停条件 |
| A12 | 收货/该单销售 | 客户实际收货后确认订单完成 | 不自动查物流、不自动完成 |
| A13 | 到账核对/财务老板 | 对照真实到账，确认通过或填问题原因 | 公账财务/私账老板；问题暂停未发货，核对不回退已发货事实 |
| A14 | 提成复核/老板有权者 | 完成且核对通过后复核当前提成 | 预估/正式区分，重审保前后差额 |
| A15 | 未发货改/取消/销售 | 改整单后核变化；或确认取消，必要时另请仓管锁回 | 金额/商品/仓变化可能重算重核；取消不等于退款 |
| A16 | 差额/运费/原操作角色 | 补凭证、补运费、处理核对问题，相关人员再核/重审 | 销售补资料不自行解除问题暂停；运费不改剩余库存成本 |
| A17 | 采购/仓管 | 实收后选1供应商/1仓，逐行SKU/数量/采购价/运费，必要预留破损阈值，核摘要→确认 | 空价不可默认0；真零价提示确认；预留破损同事务 |
| A18 | 预留囤货/仓管 | 选仓SKU、类型/数量/原因建限制，按指定记录填解锁量 | 不自动到期，不将预留放行给指定订单/销售 |
| A19 | 拆箱/仓管 | 来源仓SKU数量→目标仓不同SKU数量+原因，一次提交 | 可跨仓；人工数量，不自动单位换算 |

| A21 | 破损/仓管 | 实际换货/退款后选记录与数量，退款按需实际退款/未退运费 | 不删除入库、不回溯改原单掩盖实际损失 |
| A22 | 盘点/仓管→有权审批者 | 实盘按仓SKU，填差异原因/必要人工成本，提交→审批；库存变动需重核 | 不直接改余额，不让普通人员自审有效提交内容 |
| A23 | 采购/期初纠错/仓管→有权审批者 | 找原单填修正/原因→看影响→提交/批准；无后续影响按既有直接更正分支 | 历史成本/订单/提成影响必须保留；变化后重预览 |
| A24 | 差额处理登记/所属销售 | 线下实际补扣后标记完成 | 仅记录，不资金划转 |
| A25 | 客户维护/销售及有权人员 | 增/改地址/归档；代建指定销售；转交需老板/管理员 | 同名不跨销售合并，历史订单归属不变 |
| A26 | 商品/SKU/仓管 | 创建产品/SKU，选IP/类型/语言，编号建议后确认，可改下一号、查条码重复 | 箱/盒/包规格已删除；编号唯一、语言不猜、重复条码人确认 |
| A27 | 基础资料/有权限管理员 | 维护供应商/仓/渠道/账户/语言/人员角色；提醒全局/SKU设置 | 管理入口不等于可直接改有效业务余额；不新建管理平台 |
| A28 | 报表/各授权人员 | 按适用日期筛选库存/销售/收款/提成及导出 | 日期口径不同、三位精度/授权范围保留 |

## 5. 手机/无障碍的具体要求

- 保已定16px正文、42px单行控件和44px主要按钮/主题，不重做Logo或品牌。表单单列，选项须显示完整识别信息；价格允许3位小数，数量用整数输入。
- 当前表单根未横溢不等于账户名字可扫读；05中账户只有约103px，候选收款表单应整行账户、金额/上传/必要差额原因依次排列，不把标签和控件随意行内挤压。
- 宽明细可内部横滚，但确认按钮/总额/当前状态不能藏在横滚末列；常用列表可用可展开行，不隐藏成本访问权。
- 搜索选择器保留键盘上下/确认/退出及明确标签，报错聚焦字段，动态加载/结果保可读状态；任务切换折叠必须可键盘展开并保留输入，不新增无意义动画。
- 颜色不能独立区分“已登记/核对通过/暂停”；全部用状态文字和下一责任人。以上是下一版候选验收目标，不是本次完整无障碍通过结论。

## 6. 需要真实业务决定的变更（本方案不默认做）

1. **默认仓库/渠道/承运方/账户**：可否按人员记住上次、何时失效？本轮不静默预选真实账户/仓，不以当前单仓样本替代全系统多仓规则。
2. **一键下单＋登记收款＋交付**：是否合并持久写入/失败回滚边界？这会新增服务/API及权限组合，不是换按钮文案；首轮建议不做。
3. **自动收货、免凭证、核对＋提成一次批准、批量确认**：会改变确认职责/事实和现有门槛；首轮保留，不能靠简化界面默认批准。
4. **解锁货保护给指定销售/订单、自动单位换算、多仓/分批发货**：均是现行明确边界之外，不加入本轮UI。

布局/交互候选也尚未获具体原型批准：负责人先收口优先顺序，UI仅为选定的正常销售/采购或库存任务出稿给用户确认，再排前端实施。当前研究授权不自动恢复应用写入。
