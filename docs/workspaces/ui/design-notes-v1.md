## 设计依据

- 业务范围和状态遵循已批准的 [PRD](../../specs/PRD.md)、[项目共识](../../business/PROJECT_CONSENSUS.md)、[销售履约规则](../../business/SALES_FULFILLMENT.md)、[权限规则](../../business/ACCESS_CONTROL.md) 与 [商品规则](../../business/PRODUCT_CATALOG.md)。阶段7生产上线准备与本原型无关。
- `ui-ux-pro-max` 检索中，CRM 专属版式结果偏向营销演示页，未直接采用；只采用检索可核对的平面式视觉、移动端表格卡片化、标签清晰的表单、字段级错误提示、键盘焦点可见和减少动态效果等建议。
- 颜色采用低装饰的深青主色、浅灰绿背景、白色内容面；状态同时用文字和颜色表达，不单靠颜色。
- 不引入组件库、图标包、远程字体、动画或前端框架。布局用原生 CSS；表单控件保留可见标签与键盘焦点。

## 页面与导航

| 页面 | 主要内容 | 主要动作 / 状态 |
| --- | --- | --- |
| 销售订单 | 搜索、现有订单状态筛选、订单金额、收款核对 | “新建订单”始终作为明显入口；进入示例详情 |
| 新建订单 | 客户、渠道、交付方式、配送信息、SKU/仓库/数量/单价 | 先预览；可查看合成的成功结果或库存不足错误；预览结果显示金额/成本/毛利/提成；确认按钮只显示原型提示，不写入数据 |
| 库存与成本 | 仓库、SKU、各类数量、可售数、库存金额、平均成本、低库存标识 | 按仓库、商品和低库存筛选；窄屏按字段分组为卡片 |
| 客户 | 搜索、归档项、生日提醒、负责人和状态 | 保留新建入口；不改变客户字段与归属规则 |
| 订单详情示例 | 订单状态、收款核对状态、商品行 | 明确订单完成条件与收款核对并非同一状态 |

桌面端使用侧栏分组；手机端固定四项常用导航，并将主要内容放在底部快捷栏上方。侧栏额外列出采购、库存调整、收款核对、提成和报表等已有业务入口，但本版本不展开这些页面。入口可见性最终由现有权限决定，前端隐藏入口不替代服务端/API授权。

原型中的“角色视图（原型演示）”只用于评审老板、销售、仓管的导航差异，不表示系统提供账号角色切换。兼任角色的实际权限仍按既有规则取并集。页面链接清单只是范围示例，最终需要按页面级权限过滤。

## 交互与反馈

- 订单创建保持既有流程：填写已批准字段 → 服务端预览与校验 → 展示返回的金额、成本、毛利和提成预估 → 用户确认时才提交并占货。原型只在本地演示这两种界面状态，不调用 API；正式实现需保留既有 `operation_key`、`preview_token` 和 CSRF/session 机制。
- 库存不足时，在表单相关 SKU 行附近说明仓库、商品和原因，不给失败预览显示提交按钮，不改变库存。
- 快递与现场交付沿用现有规则：快递需要收件信息，现场交付可不填；原型切换现场交付时隐藏地址组。
- 订单状态采用现有五类；到账核对单独展示“未登记 / 待核对 / 已通过”等既有状态，凭证登记不表述为到账通过。
- 表格筛选保留当前页面查询模式；新建、筛选和原型预览有明确按钮与反馈。无数据状态应说明当前筛选结果为空，并提供清除筛选入口（后续实现时按现有页面行为确认）。
- 错误同时放在相关字段/明细旁，并在需要时将焦点移到错误信息；按钮禁用状态及提交结果需可感知。

## 响应式与可访问性

- 从 320–390px 窄屏开始布局；表格切为每条记录一张卡片并显示字段名，避免页面整体横向滚动；操作按钮目标高度至少 42px。
- 中等屏幕收窄侧栏与表单列，宽屏保留完整表格和多列表单。
- 所有表单使用可见标签，保留键盘操作和高对比度焦点环；状态不只依赖颜色；支持减少动态效果偏好。
- 订单多明细、宽屏表格和真实浏览器的屏幕阅读器行为仍需用户批准后由实现与测试阶段验证。

## 验收要点（用户批准后供前端/测试使用）

1. 具备对应权限的销售能从明显的新建入口开始创建订单；没有权限的账号看不到入口且直接访问仍由服务端拒绝。
2. 表单按已批准业务模式展示字段；预览结果与服务器响应一致。预览失败能指出不足的仓库与SKU，确认前不占货；重复提交继续沿用现有幂等规则。
3. 快递地址必填，现场交付允许省略地址；付款凭证、收款核对、发货、收货和提成状态不会被合并或误标。
4. 库存可区分在库、占用、预留、囤货、破损、可售与成本；数量单位保持清楚。
5. 桌面 1280px、平板 768px、手机 390px 和 320px 窄屏下，主要入口、表单字段与反馈均可操作，页面无整体横向溢出。
6. 键盘可访问所有操作，焦点清晰；字段错误可定位；加载、空结果、权限拒绝和服务端错误均有明确反馈。
