## 本轮参考与观察

### 门店 Logo

用户在 2026-10-08 提供的图像包含“ALOLA / 阿罗拉潮玩空间”字样、深靛紫色几何字形、橙金色卡片图形和问号。v2 使用品牌名称、深靛紫主色和少量橙金强调点作为灵感，不把 Logo 图形嵌入应用导航，也不改造或重绘品牌标识。

### 小程序 UI

用户指向的目录实际名称为 `~/Downloads/新修改页面 `（文件夹名末尾有空格）。只读检查了 `首页V6.html`、`我的订单V6.html`、`订单详情V6.html`、`仓库管理V6.html` 和 `底部标签栏设计.html` 的 HTML/CSS 源码，没有执行其中的脚本，也没有用浏览器渲染这些本地文件。源码中反复出现的视觉参数包括：

- 主色 `#302c6c`、深色文字 `#28293f`、辅助文字 `#6f7593` / `#9aa0b5`、背景 `#e9edf6`。
- `Noto Sans SC` 优先的中文无衬线字体栈、390px 手机画布、18px 卡片圆角、底部标签栏。
- 多个页面使用渐变背景、发光层和半透明玻璃卡片。

### 技能的适用范围

- `ui-ux-pro-max` 适用于本任务：v2 保留可见字段标签、键盘焦点、状态文字与颜色并用、窄屏触控尺寸，以及窄屏表格转卡片的结构。原型定义了 320px 起的响应式规则，但尚未在真实浏览器视口验证。
- `design-taste-frontend` 的说明明确将数据表和多步骤业务后台列为不适用的目标。本轮只使用它的品牌保留、审慎锁定颜色和形状规则；不套用营销页布局。小程序中的玻璃拟态和大面积渐变没有照搬到 CRM，密集业务数据使用不透明白色表面和轻量阴影，以保持阅读对比度。
- `vision-analysis` 所要求的 MiniMax 图像 MCP 工具在本会话不可用，访问其技能说明中的官方配置页面也超时。本说明的 Logo 观察来自当前会话里用户提供的可见图像，不声称经过 MiniMax MCP 分析。

## 版本与设计范围

v2 基于 v1 的同一套业务信息架构和交互示例，仅调整品牌表达及视觉样式。范围仍为：

1. 销售订单列表：搜索、现有五种订单状态筛选、订单金额和收款核对状态分开显示；新建订单入口醒目。
2. 新建订单：现有客户、渠道、交付方式、配送信息、SKU、仓库、数量、成交单价字段；本地演示预览成功和库存不足两种结果。成功示例展示金额、成本、毛利、提成预估；不足示例不显示确认提交按钮。
3. 库存与成本：按仓库/SKU 查询，区分在库、占用、预留、囤货、破损、可售、库存金额、平均成本及低库存状态。
4. 客户列表：搜索、归档项、生日提醒、负责人和状态。
5. 订单详情示例：明确订单履约状态与收款核对状态是两类状态。
6. 桌面侧栏、手机底部快捷导航，以及老板/销售/仓管三种导航示例。

角色选择器只帮助用户在原型中查看导航差异，不表示真实系统具有切换角色功能。真实入口仍由现有权限控制，服务端授权是最终边界。未展开的采购、库存调整、审批、收款核对、提成及报表仅作为既有页面导航提示，不在本版模拟新流程。

## 已批准流程边界

下单仍是填写已批准字段 → 既有服务端预览与校验 → 展示服务端计算结果 → 用户确认后提交并占货。真实实现须继续使用既有的 `operation_key`、`preview_token`、Django session/CSRF 和服务端权限检查。v2 示例是纯本地原型，不发送 API 请求、不创建订单、不修改库存或数据库。

快递与现场交付、收款凭证与到账核对、订单完成与提成正式计入继续保持各自已批准的状态条件。数量、成本、收款、提成及权限规则不由视觉原型推断或更改。

## 品牌与界面样式映射

| 设计来源 | v2 用法 |
| --- | --- |
| Logo 深靛紫 `#302c6c` | 主按钮、导航选中态和品牌标记边框 |
| Logo 橙金 | 小型品牌标记强调点；不承担小字号正文或状态文字颜色 |
| 小程序浅蓝灰 `#e9edf6` 与紫灰文字 | CRM 页面背景、次级文字和控件边线 |
| 小程序白色圆角卡片 | 用于订单/表单/表格分组；不使用透明玻璃表面 |
| 小程序底部标签栏 | 手机端提供四个常用文本快捷入口，保持页面标签可辨识 |

布局使用原生 HTML/CSS/JavaScript，没有外部字体请求、组件库、图片资源、SVG 图标或前端框架。卡片采用 18px 圆角、操作控件采用 10px 圆角，状态徽标为胶囊形。主按钮维持靛紫底白字；暖橙只作点缀。
