## 提请确认的设计

1. 下单依次为客户与交付→商品明细→本单开票与备注；已有客户/新客/散客用一组切换。姓名、联系方式为新客单行输入，不再做大多行框。
2. 所有页面删除顶部栏，账号移至侧栏底部；短字段固定合理宽度，手机单列，数量/单价短框，地址及备注适度加宽。客户、SKU及仓库查找融入可输入的选择框，不把三次查找按钮摆成必做步骤。实施时仍需真实候选、已选值、加载/无结果/失败旁显；本原型仅原生datalist合成选项，没有完整异步查询/选择验证。
3. 已有客户选中地址后，收件信息可展开查看/修改；新客快递收件信息直接展开。现场交付不展示快递区。收件人不默认继承新客户姓名。
4. 选品相邻呈现所选仓可售数量与单位；数量/单价为短输入，金额汇总固定在桌面右侧，手机在表单末尾。提示库存以提交校验为准；不把原型可售值/浮点小计作为业务实现。
5. 开票默认不展开，勾选才显示抬头必填、代码/邮箱选填。已有资料与新填写切换；新客只新填写，提交成功才同步客户，订单快照含义明确。散客不建档、无需开票；切换散客隐藏开票选择和资料，并清空本单勾选及开票字段，汇总恢复“否”。返回客户模式不会恢复散客切换前的本单开票选择。
6. 客户用备注1/2替代生日、兴趣爱好；开票资料作为独立选填组。没有完整度标记/生日提醒。主页面仅搜索/新增入口/列表；点击客户弹窗详情，弹窗内编辑和模拟保存。地址仍使用既有地址维护流程，本版没有完整制作多地址新增/编辑。模拟保存仅在当前弹窗显示，不持久化或改变列表。
7. 商品创建在前台商品档案体系中，先共有资料再实际SKU，语言为后台维护下拉（简中/日文/英文/韩文），无默认，补充包和礼盒·预组必选、周边可空；管理页仅增加维护入口示意。编号按既有IP前缀显示最大号及下一号建议、允许修改，不预占号、不新增自动编号。商品/规格别名均为可增删单行。保留包装说明和可空条码。创建权限不扩给销售。产品/SKU完整服务端校验、重复条码确认待现有服务复用，不由此HTML定义。
8. 管理后台示意品牌外壳、简体中文标签、分组入口；不是另建管理应用，也不是全部Django Admin字段主题已交付。期初只在管理入口，演示关闭态，不在日常导航；尚未入账时老板/管理员可重开；一旦入账永久禁止重导、覆盖或追加，最终权限及状态由服务端落实。
9. 工作台卡片内容自然高、顶边对齐，空提醒紧凑；保留员工必要口径，删除接口/查询全集等开发文字。待出库/收款/低库存数量并入对应标题，不另放重复统计卡。趋势改折线图；新增客户总数＋今日新增（沿用账号可见范围）、商品IP＋语言组合数量及档案入口。所有数字/趋势为合成示意；组合数量示意不代替后端统计契约，周边空语言如何计数尚需公共收口，不在原型映射。
