# 提成差额局部接入：最小开发交付

2026-10-20。具体人类批准及三项冻结SHA见[UI WORK唯一审批栏](../WORK.md#当前提成差额局部接入批准commission-adjustment-inline-v1-1020)，源文件见[SHA256SUMS](SHA256SUMS)。设计/字段/边界直接沿[README](README.md)，不另复制业务合同或修改三源。

## 前端范围

- 按负责人唯一应用写入安排，仅接现有`adjustments`已生效纠错影响明细内局部；原纠错/changes/原因/审批结果保留。不新增页面导航、金额输入、审批层、历史API、批量或默认自动adjust。
- 消费同一纠错`before_after.commission_adjustment_suggestions`及既有可见资料；逐订单呈现当前核定/新计算/差额与两个按钮。订单链接到现有详情；销售名无现成数据就隐藏，不批量请求补名。
- 请求/直接返回字段按README所引真实API合同；端点无尾斜杠，不传金额，复用现有幂等/重试及中文失败反馈。权限、完成/付款核对和版本条件以服务为准，不以隐藏按钮代替授权。
- 过期/条件不满足，禁旧决定并给刷新入口；刷新使用新响应，没有建议不重启旧行。决定成功仅以本次真实结果更新摘要/操作记录标识；keep不当资金调整，adjust不当已转账。刷新后不承诺完整已处理历史列表，不用本地存储伪造历史。
- 保留现有主题/字号及1280/390可读性，金额完整读取，手机按钮至少44px。候选演示按钮、合成身份/记录号/金额及定时内存逻辑不得进入真实应用。

## 固定交付后

前端固定提交并停止应用写入，交独立QA及负责人，通知UI按该局部1280/390复核：有/无可见建议、两种决定结果、版本/条件失败与刷新、提交中及失败恢复、金额/按钮和本次摘要。权限/幂等/资金与真实业务由QA验证；不重跑已通过v2五项或全站主题矩阵。

未定义的接口数据/范围冲突先报负责人，不擅补服务。UI承接设计疑问，无法按现合同解决则升级；用户设计批准、独立技术验收与发布分别记录。
