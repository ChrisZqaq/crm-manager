# 企业微信自建应用接入研究

查证日期：2026-10-20。范围：只读研究；不改应用代码、域名、SSH、服务、账号或网络配置，不做真实 OAuth 联调。

## 建议

把自建应用作为企业微信工作台中的 CRM H5 入口，首期只接入企业微信网页授权登录；CRM 仍以 Django 用户、角色和权限为准。授权成功后，服务端用企业微信返回的成员 `userid` 查找明确绑定的既有 CRM 用户，再建立原生 Django session。应用可见范围不是登录白名单；首批只绑定获准试点账号，并拒绝未绑定或 CRM `is_active=False` 的用户。成员的姓名、销售员ID、手机号和非成员返回的 `openid`/`external_userid` 均不能作为 CRM 员工登录身份；不自动创建用户或分配角色。

单企业场景下，最小候选是在既有 `AccountProfile` 一对一关联 Django 用户的基础上增加唯一、可空的 `wecom_userid` 绑定字段；模型当前只有 `user` 和 `version`。实施前核实正式库现有员工的 profile 覆盖情况；若有缺行，可先评估对绑定用户 `get_or_create` 或用最小数据迁移补齐。暂不引入独立身份框架。已记录的企业微信参考标识只在私有交接资料中，不应把值复制到代码仓库或普通文档。

## 平台能力与限制

- 企业管理员可在“应用与小程序 → 应用 → 自建”创建应用，设置应用信息和可见范围；应用主页可作为工作台进入 CRM 的 H5 URL。应用的 `AgentID` 和 `Secret` 用于相应服务端 API。[自建应用简易教程](https://developer.work.weixin.qq.com/document/path/90487)
- 网页授权使用 `CorpID`、`AgentID`、回调 URL 和 `snsapi_base` 获取静默授权码，再由服务端调用 `auth/getuserinfo` 获得成员 `userid`。授权码一次有效、约 5 分钟过期；回调域名必须与应用可信域名匹配。官方明确企业成员即使不在应用可见范围内也可能返回 `userid`，因此可见范围不能代替 CRM 登录白名单；非企业成员返回 `openid` 或 `external_userid`，不应映射为员工账号。首期只需员工身份时，不申请手机号、邮箱等敏感信息。[构造网页授权链接](https://developer.work.weixin.qq.com/document/path/91022) [获取访问用户身份](https://developer.work.weixin.qq.com/document/path/91023)
- 企业微信可信域名不支持 IP 地址或短链域名；配置主体需是已验证企业，域名需能在工信部备案体系查询并通过所有权校验。每个应用只能配置一个 OAuth 回调域名；JS-SDK 域名另有设置项。**因此现有 IP:18888 测试入口不能作为 OAuth 可信域名使用。**[企业微信开发者帮助：网页授权及 JS-SDK](https://open.work.weixin.qq.com/help2/pc/15372)
- 正式 CRM 远程访问还必须满足本项目既有 HTTPS 要求。平台后台需配置自建应用、可见成员范围和可信域名；CorpID、AgentID、Secret 等凭证由管理员在获批实现时安全配置。官方页面标题为“获取access_token”，正文接口是 `GET https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=ID&corpsecret=SECRET`，并要求 `access_token` 留在服务端缓存、不能返回前端。[获取 access_token](https://developer.work.weixin.qq.com/document/path/91039)
- 应用消息推送、接收消息/事件回调和客户联系接口均为可选能力，不是 H5 入口或 OAuth 登录的前置条件。消息推送适合明确的 CRM 通知需求；回调须有可公网访问的服务端 URL 和验签/解密处理；客户联系接口需管理员另行配置“可调用接口的应用”及成员范围，并定义企业微信客户与 CRM 客户的匹配规则。[发送应用消息](https://developer.work.weixin.qq.com/document/path/90236) [回调配置](https://developer.work.weixin.qq.com/document/path/90930) [获取客户列表](https://developer.work.weixin.qq.com/document/path/92113)

## 本项目现状与影响

- CRM 使用 Django 原生认证用户；HTML 与 API 均先要求登录，再按 `request.user` 的 Django 权限和角色组授权。Admin 员工管理维护 `is_active` 和角色组。企业微信登录应复用此用户和权限体系，不能把企微应用可见范围当作 CRM 业务授权。
- 项目已有 `crm.models.AccountProfile`，通过 OneToOne 关联用户，目前 `version` 是其唯一业务字段；从当前可见模型代码无法确认所有已存在用户都有 profile。优先核实缺行情况，考虑仅在 profile 加可空唯一绑定字段并为绑定用户补齐 profile。
- 最新项目状态记录：应用 `6024205` 的限定验收已完成，但部署运行仍是 `71cf9f6`、迁移 `0015`。文档最后记录云端测试入口 `18888` 服务测试库，业务库与测试服务隔离且没有正式 Web 入口；本机 `8765` 于 10 月 19 日恢复为本地只读审查副本。以上是最近文档证据，不是本次在线探测结果。新版业务数据重建、正式入口/切换和上线恢复条件仍未完成，因此不能把企业微信应用直接指向当前测试入口或把 OAuth 接入等同于正式员工切换。见[开发计划](../../project/DEVELOPMENT_PLAN.md)、[发布记录](../../project/RELEASE_COST_WORKFLOW_20261020.md)、[部署记录](WORK.md)。

## 最小实施步骤及验收

1. **先确认目标环境并准备域名。** 确认业务数据重建与版本发布后要接入的 CRM 环境；管理员提供已备案且归企业验证主体管理的域名、DNS/所有权校验配合和 HTTPS 访问入口。用企业微信可信域名设置验证通过、办公网络及手机/桌面企业微信可打开登录页作为验收。当前 IP 测试入口不满足 OAuth 条件。
2. **实现并小范围试用 SSO。** 由管理员创建自建应用并设小范围可见成员；服务端发起 OAuth、校验随机 `state`，换取并验证 `userid`，按唯一绑定找到 `is_active=True` 的现有用户后调用 Django 登录。只绑定获批试点账号；未获批绑定的成员即使 OAuth 返回 `userid` 也拒绝登录。企微可见范围由管理员维护，不能代替 CRM 登录白名单；未绑定成员、非成员 `openid`/`external_userid`、重复绑定和 CRM 停用账号均拒绝。另验证错误/重放/过期授权码、角色权限、Admin 访问，以及 CRM 原有 CSRF/session 边界。凭证只保存在服务端受控配置中。
3. **独立验收后再决定扩大范围。** QA 用合成数据和授权试点账号分别检查登录、退出、角色权限和撤权。企微离职/移除成员不会自动停用 CRM 账号；首期无通讯录同步时，管理员需同步停用 CRM 用户。另验证 CRM 用户停用后的既有 session 是否立即失效；如否，再决定增加服务端状态校验。负责人确认固定版本和数据入口后，才另行决定部署或扩大范围。消息通知、回调、客户联系另立用例，不含在首期。

## 已确认资料与待确认项

- **已确认的前置资料：**负责人转述用户在负责人会话直接确认企业微信已完成企业验证、用户有管理员权限、`onenesscyber.tech` 已完成ICP备案。负责人另报告只读DNS检查中根域名有A记录而 `crm.onenesscyber.tech` 无响应；后者只是候选回调/访问域名，尚未配置。此处引用会话确认和负责人检查记录，本研究未独立访问控制台或重新查询DNS。
- 仍需确定实际使用的子域名、可信域名所有权校验、HTTPS证书与终止位置。部署记录显示Certbot命令曾因依赖错误失败、续期未验证；`crm.onenesscyber.tech` DNS尚无响应。用户未授权改DNS、签发/配置证书或改云服务，后续须在具体实施方案中另行安排。
- CorpID/AgentID及首批试点绑定由管理员在受控实施环节提供和配置，**Secret 不要粘贴到聊天、报告或 Git**；还需明确目标 CRM 版本、正式业务 Web 入口，以及员工userid绑定和离职时停用CRM账号的责任人。当前 9 个正式账号状态和新版业务重建不可视作员工切换授权。
- 仅当首期登录通过后，才需决定是否需要消息推送、通讯录/客户联系数据或 JS-SDK 能力，并按最小权限说明业务用途。
