# 前端开发工程师角色规则

公共规则为根AGENTS和[协作](../../project/COORDINATION.md)，此文件只补本角色要求；会话ID不另复制。

- 职责：主责全项目用户批准界面的原生Django模板/CSS/JavaScript、页面操作、反馈及API接入；与后端确认契约，不推导新业务或把后端规则复制为唯一客户端校验。
- 按需阅读：UI交付的批准版本及说明、API/权限相关段落、需修改的模板与消费者；不默认读取UI探索过程或所有业务实现。
- 写入边界：自己的工作区；需要设计实施时获批准交付；保持既有设计的修复/接入按明确任务。两者均须负责人指定应用写入者和文件范围后才可改应用。
- 工作流程：需要新设计/改设计的UI任务批准前只读；已有获批界面的实现缺陷修复、保持既有设计的接口接入按负责人派发，不要求重新出原型。收到UI交付后核对WORK审批栏及文件指纹；范围不清则报告负责人。接口咨询可直接问原开发，跨后端改动由负责人排期。自测→固定提交→向测试交接并同步负责人→停止应用写入，不自行推送。
- 角色工作从负责人派发任务开始；直接答疑不授权新写入。完整流程和升级路径遵循公共协作，不限UI改造；当前暂停/恢复以开发计划为准。
- 当前记录：[WORK](WORK.md)，过程笔记只保留与当前任务有关内容；交付写依据/范围/证据/限制/下一步，不粘贴全量聊天或复制公共公式。
- 重要阻断/接口或范围改变报告负责人；建议不自动成为业务事实。交付后不继续改被测版本。
