# 待办优先界面调整：原型范围

2026-10-23。状态：用户已确认方向及职责边界，尚无具体原型批准；仅设计，不改应用或正式环境。固定应用基线d47fc91/CRM0018。

## 用户确认

用户用手机、分别登录不同角色试用，电脑亦存在信息混杂问题。首页应首先提示本人需要处理的事项；订单页面按当前用户在该订单的职责及状态组织，不因拥有某权限就平铺全部可写表单。老板允许自己销售，但他人销售订单不向老板展示销售登记收款/出货等代办修改入口；发现问题退回原负责人员修改并重新提交，不由老板代改。所有具备仓管职责及相应权限的人员可见待发货事项，谁实际处理谁操作，暂不引入个人指派/抢单模块。

减少常驻说明：日常只保必要标签、数据及动作；格式/容量等帮助按需展开，实际错误就近提示，影响操作结果的校验和确认不得删除。单行输入与按钮统一尺寸，多行地址/备注单独排布，不能通过缩小字号降低文字量。

## 本轮原型

只新增独立原型docs/workspaces/ui/task-focused-v1/，保持既有品牌/米绿主题。覆盖待办首页、订单列表必要入口及订单详情/当前操作，桌面1280和手机390；以合成角色/订单演示，不复制截图的真实商品、金额或人员。

- 首页先给本人待办数量及直达操作入口；其他查询/统计次要。多职责可并存，不做人工角色切换作为操作前置。
- 订单列表显示可辨识客户/商品摘要、金额、状态及本人待办；详情顶部清晰呈现当前任务与按钮，无待办不编造动作。
- 当前操作点击后展开最少字段，完成后收起并显示结果；收款记录/物流/商品/提成等只读信息按需查看，偶尔修改不常驻。
- 老板他人订单仅显示其应办核对/审批/退回及有权限的只读内容；老板本人销售订单仍按实际销售职责处理，不能把老板一律排除销售流程。
- 以现有订单履约与收款/提成状态作为依据。同一单可同时存在不同职责待办，不能强制成一条新的串行流程；未核对可发货、问题暂停出库等现行规则保留。
- 运费调整、文件限制、金额版本、配色切换等从主要操作区域移出或隐藏技术信息；不得擅自删除现有可用业务能力或后台必要证据。

## 退回与安全边界

收款退回复用现有待处理+原因，由销售补正再交原核对人员；未发货暂停、已发货不倒退。不能用新“退回”字样回滚实物出库、收货或已计入提成。提成、采购纠错、盘点等已有不同审核规则；若原型发现“退回修改/重提”缺对应实现，明确标未决并报负责人，不自行增加状态/API或猜重提条件。第一轮不设计跨所有模块的通用审批平台。

按单隐藏入口与服务端授权是不同工作；此阶段不改老板/管理员角色组或全局权限。实施前需核对现有授权能否满足已确认的他人订单职责边界，不能只隐藏表单就称访问控制完成。

## 交付与停止

UI先核现有实现（图发现优先），用合成状态做可点击原型，给出短的角色/订单状态呈现对照及未决点；交用户批准具体版本。未批准前前后端均停写，不部署原型到正式入口。独立QA在实现固定后再派，不立即重跑全套。真实图片不入Git；真实期初/客户/流水核对与导入继续暂停。公开商品资料调研独立进行，不将新SKU构想混入本轮。
