## 建议顺序

1. 销售登录，查看工作台、商品档案、库存。搜索DEMO-0001，打开商品详情检查语言、包装类型、售卖单位、SKU别名和SKU状态（箱/盒/包规格已删除）；库存明确仓库、单位、在库、可售及占用。迁移及试用后的最新数量以页面为准，不能用旧演示数字判断。
2. 用虚构客户资料新建客户及收货地址；不要使用真实姓名、电话或收款记录。
3. 新建一单1盒、单价120.000、出库运费0，选择演示仓库和可用渠道。检查提交前成本/金额，提交后订单占用增加1、可售减少1、实物在库不变。另建一单再取消，检查释放占用；库存不足应明确拒绝。
4. 在订单详情登记收款，选演示账户、金额120.000，上传一张普通测试PNG/JPEG作为虚构凭证。未上传应阻止进入待出库；另测金额不符，需要原因才能确认，但不代表核对通过。上传不能使用真实凭证。
5. 仓管登录，按该单选择演示运输方式与虚构运单号，确认整单发货。应扣实物数量、释放该单占用；销售确认收货后订单完成。若测试现场交付，不要求物流编号。已发货不能直接改SKU/数量/仓库。
6. 老板登录，在收款核对页面按对应演示账户核对；再复核提成。完成订单＋核对通过＋老板复核后才正式计入；上述1盒示例毛利20.000、提成2.000（成本保持100.000且运费0的前提）。未发货时核对标问题应暂停出库，可再通过核对解除；别用修改订单绕过暂停。
7. 查看库存、销售、收款核对、提成四报表，筛选后导出Excel，比对筛选/金额/数量。订单列表日期按下单日，销售统计默认按发货或现场交付日；下单未发货不进入默认销售额。
8. 老板/仓管补测采购入库、预留/囤货、拆箱/赠送、破损、盘点调整与采购纠错。这些会改变演示数据，先记录单据编号和操作前数量；盘点/纠错按现有审批，不直接编辑库存余额。先完成正常销售链路，再测这些模块。

## 反馈方法

记录账号、页面、单据/SKU编号、操作步骤、预期结果与实际结果；界面问题附截图，金额/库存问题附前后数字。说明是否可重复出现，不必整理技术日志。不要在反馈中提供真实凭证或密码。

## 环境边界

本机与云端测试数据独立、不自动同步；云端IP入口由部署工程师单独验证后交付。HTTP云端测试不输入真实客户/付款资料。此指引供人工业务试用，不代表最新代码全量测试或正式上线验收。
