## 用户已确认的补充规则

1. 每客仅一套开票资料，订单保存当次快照；订单新填资料同步客户但不改历史订单。
2. 开票由财务和老板在线下处理；本系统记录本单是否需开票及资料，不接税务、不执行开票。勾选开票仅抬头必填，信用代码/邮箱仍选填。
3. 接受客户姓名、联系方式及快递交付资料必填；公司、备注及开票资料选填，选填缺失不标档案不完整。不新增客户完整度标记或待补全任务。
4. 散客不建客户档案，也不需要开票；订单散客模式不开放开票，服务端亦校验，不能只靠隐藏控件。
5. 旧兴趣与爱好分别转入备注1、备注2；删除生日数据及提醒功能，保留不可破坏的历史业务操作关联。
6. 老板／管理员在尚未入账时可以重新开启期初导入；成功入账后仍禁止重复、覆盖或追加。
7. 此前用户继续审阅；现已在UI会话明确批准冻结版本，见下方最新记录，不能仅凭早先三项业务答复推定批准。

以上于2026-10-09用户逐项确认，后端方案可按此收口；应用仍等待当前固定验收结束与负责人排定写入窗口。不能把选填字段缺失当异常，不能猜测收件人一定是客户本人。
