# 登录、角色与权限共识

## 最小登录

- 第一版支持账号密码登录，复用框架现成登录及安全密码存储。
- 不做公开注册、短信验证码、复杂权限规则引擎或多级审批。
- 权限由后端检查，隐藏界面按钮不能替代授权验证。

## 角色与权限开关

- 普通角色为销售、仓管／财务、老板，员工可兼任，权限取并集。
- 后台按角色为每个实际业务操作设置开关；不做个人权限覆盖，不为每个输入框设计权限。
- 提交与确认是不同操作，应分开设置，例如采购纠错提交和确认、盘点登记和确认。
- 老板及管理员可管理普通角色权限与员工普通角色；老板若要最高权限，可以同时拥有管理员身份。
- 只有管理员能授予或撤销管理员身份；管理员身份不受普通权限开关限制，不能通过普通角色开关取得管理员身份。
- 权限变化后后端按有效配置检查操作；必要记录包括修改人、修改内容和时间，不扩展完整操作审计平台。
- 第一版保持固定角色和预定义权限项，不增加自由规则表达式或任意数据过滤条件。

## 默认范围及开关目录方向

- 商品信息对所有人员一致展示，包括成本，不设置成本字段隐藏。
- 客户、订单及提成默认只查看本人范围；额外设置“查看全部”开关，兼任多个角色时按有效权限处理。
- 销售兼任仓管后拥有仓管全部权限，不另设简化仓管角色。
- 下列目录指导后续界面及 API 权限设计；具体默认开关逐项按业务责任落实，不把可查看直接等同于可修改。

| 权限组 | 预定义开关方向 |
| --- | --- |
| 基础资料 | 商品、仓库、供应商、收款账户维护分别设置 |
| 客户及订单 | 客户维护、订单创建及修改、取消、查看全部客户、查看全部订单分别设置 |
| 库存操作 | 采购入库、预留解锁、囤货管理、出库发货、拆箱、赠送分别设置 |
| 盘点 | 登记／提交、确认调整分别设置 |
| 采购纠错 | 提交、确认分别设置 |
| 收款及提成 | 收款核对、查看全部提成、提成复核、确认本人补扣完成分别设置 |
| 交付 | 确认收货、确认现场交付按实际操作分别设置 |
| 后台管理 | 员工管理、普通角色权限管理分别设置；管理员身份授予不由这些开关授权 |

- 收款核对仍遵守账户责任：对公由财务，老板私账由老板直接核对；权限开关不自动改变账户核对责任。
- 老板亲自提交采购纠错或盘点调整时允许自己确认，仍需保留提交及确认记录。
- 账号初始化、最终各角色默认开关及其他角色自行审批边界在实施设计时明确，不自行推定。

## 管理员与业务约束

- 管理员是超级角色，具有全部业务权限及权限管理能力。
- 超级权限不跳过业务完整性规则：不能超卖或产生负库存、缺采购价正式入库、跳过必填收款截图、直接改库存余额。
- 收款问题暂停出库、纠错重算和必要审批记录等要求仍适用，不因管理员身份抹去。
- 不开发管理员绕过校验的后门。

## 最小验收方向

1. 员工兼任角色取得并集权限，未获授权的 API 请求被拒绝。
2. 普通开关不能授予管理员身份，非管理员不能修改管理员身份。
3. 老板和管理员能管理普通权限；管理员不受开关关闭限制，但仍受业务校验约束。
4. 无查看全部权限时不能访问其他销售的客户、订单和提成；商品成本对所有用户一致展示。
5. 老板自提交自确认有记录，权限变更保留修改记录。
