# 商品档案共识

确认日期：2026-10-02。本文记录商品模块已确定的逻辑结构，不代表数据库物理结构、字段类型或接口已经确定。

## 层级与范围

- 商品分为卡牌和周边，IP 必填。
- 层级：IP → 可选系列 → 产品 → SKU。世代和系列合为一个可选系列，不做任意层级分类树。
- 系列为空时，直接由 IP 展示到产品，不增加“未分类”层级。
- 周边按 IP → 周边 → 商品名查找；“周边”是商品类型，不是系列。
- 产品表达商品身份，SKU 表达可采购、占货和出售的具体规格；只创建实际经营的组合。

## 逻辑字段

| 层级 | 字段与规则 |
| --- | --- |
| IP | 名称；产品必须关联 IP |
| 产品 | IP、类型（卡牌／周边）、系列（可空）、产品名、语言版本、官方编号（可空）、多个别名 |
| SKU | 唯一且稳定的内部编号、箱规格说明、包规格说明、包类型（瘦包／肥包／空）、售卖单位、真实包装条码、多个规格别名、启用状态 |
| 仓库库存 | 每个仓库＋SKU 对应的在库、订单占用、客户预留、囤货、破损待处理数量和库存成本 |

- 包类型与售卖单位独立：瘦包或肥包商品仍可按箱、盒、包出售。包类型可空，预组套装通常按盒出售。
- 箱规格和包规格为可选说明文本，例如20盒/箱、40盒/箱、5张/包、20张/包、6张/包；不将肥包或瘦包硬编码为张数。
- 最新模板规则增加包规格说明，替代此前完全不保存包张数说明的简化决定；仍不增加独立数字张数或自动换算体系。
- 不保存发售日期。
- 不维护箱、盒、包的自动换算。拆箱库存和成本转换见 [项目共识](PROJECT_CONSENSUS.md)。
- 公仔不同尺寸或颜色分别命名、分别建产品和 SKU，不增加通用颜色、尺寸规格体系。

## 语言版本与官方编号

- 简中、日文分别建产品，不强制共用名称或建立跨语言对应关系。
- 按用户提供的例子：“共逐荣光”（简中，SCV10C）与“火箭队的荣耀”（日文，SV10）分别登记。
- 语言和官方编号放在产品层；同一产品的瘦包、肥包及不同单位 SKU 共用这些信息。
- 官方编号不作为内部唯一标识，不要求全局唯一。
- 2026-10-03确认：卡牌产品语言版本必填，由人员明确填写或选择，不默认简中；周边语言可以为空。语言保存在产品层，同产品各SKU共用；导入卡牌语言为空时提示具体行，补齐后才能正式导入。

## 编号与条码

- 内部 SKU 编号唯一且稳定，商品改名不改变编号。
- 2026-10-03确认：内部编号采用IP前缀＋至少4位流水号，各IP独立编号，例如PK-0001、RB-0001。第一版人工填写，系统检查格式和全局唯一性；超过9999继续10000，不设4位上限。每SKU单独编号，不将语言、售卖单位等含义编码进去。
- 编号使用后保持稳定，改名不改号，停用不复用；已确认宝可梦PK-、符文战场RB-，其他IP前缀由用户指定。
- 条码来自真实包装，包括已有银豹条码，不是人工生成的 SKU 编号。
- 箱、盒、包各自使用对应包装条码；条码不替代内部 SKU 身份。
- 2026-10-03确认：包装条码允许为空；重复条码允许保存或导入，但必须提醒、展示已对应SKU并由人员确认。查询同一条码匹配多个SKU时展示候选，不自动选中。条码按文本保存，保留前导零；内部SKU编号仍必填且唯一。
- 数据库关联使用独立内部ID，不以可读SKU编号作为外键。以后修改编号格式可用于新建SKU，历史编号仍保留有效，不按新格式追溯判错；目前不开发批量改号、编号别名或历史映射工具。

## 别名与查找

- 产品和 SKU 都支持多个别名；别名不要求唯一。
- 产品别名示例：“17.5”“18.0”；规格别名示例：“17.5肥”。
- “17.5肥”指该产品的整个肥包规格，不默认指一箱；如有多个售卖单位，返回对应 SKU 选项。
- 同一个别名可以匹配多个语言版本或产品，例如“18.0”；结果显示语言、产品名、包规格和售卖单位，不自动猜选。
- 支持 IP、系列、产品名、官方编号、内部 SKU 编号、条码、别名的普通包含匹配，完整匹配优先。
- 支持按 IP → 可选系列 → 产品 → SKU 浏览，也可按商品类型筛选。
- 不引入向量库、跨语言自动映射或复杂搜索服务；Agent 查询遵守相同的歧义处理规则。

## 库存、价格和统计的边界

- 仓库不是产品的单一字段，同一 SKU 可同时存在多个仓库。
- 成本按仓库＋SKU 管理；商品页面显示成本时标明仓库，不使用一个成本覆盖所有仓库。
- 不保存参考售价和商品参考毛利率；订单人工填写成交价，保存正式提交占货时的成本快照，计算订单实际毛利。人工预留先由仓管解锁再正常下单，详见 [采购入库](PURCHASE_RECEIVING.md)。
- 首次入库时间、累计入库、销量与其他出库从有效业务记录计算，不作为可直接修改的商品字段。
- 累计出库不等于销量，拆箱、赠送等分别解释；统计数量携带单位，不把箱、盒、包直接相加。支持同仓或跨仓拆箱，分别记录来源及目标SKU的数量和成本；第一版不做保持SKU不变的独立仓库间调拨。
- 低库存提醒已确认单一全局默认阈值，入库时可填写SKU专用阈值或关闭该SKU提醒；专用值及关闭状态保存在SKU、各仓共用，各仓按自己的可售数量判断。全局默认初始为5，后台另有全局提醒开关，关闭时所有SKU不提醒但保留配置。不区分售卖单位、不做仓库例外或三个模式选项，见 [项目共识](PROJECT_CONSENSUS.md)。

## 最小数据组织方向

- IP 档案、产品档案、SKU 档案分别表达；仓库库存属于库存模块，关联仓库和 SKU。
- 系列先作为产品的可选文本，提供已有值选择，不增加系列树。
- 期初导入按IP、类型、系列、产品名、语言、官方编号一致识别同产品候选，人工确认归属预览后入账；共有资料冲突提示核对，不做模糊归并或静默覆盖。规格SKU共用产品资料，但数量及成本各自独立，见 [期初与导出](INITIAL_DATA.md)。
- 别名按字符串列表表达，暂不增加独立别名管理模块。
- 数据库金额保存精度为小数点后 3 位，采用高精度十进制计算及统一四舍五入，详见 [销售履约](SALES_FULFILLMENT.md)。数据库物理表和唯一约束等在下一步设计时明确；模板字段见 [期初与导出](INITIAL_DATA.md)。
